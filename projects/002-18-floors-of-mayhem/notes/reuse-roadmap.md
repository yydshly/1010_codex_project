# 复用与扩展路线

> 此路线是 2026-10-10 的原始方案。后续樱街守灯夜已实现有限任务与行动 NPC，机甲已实测动态指挥；多人小镇和通用任务编辑器仍未完成。最新进展见 [完整汇总](research-summary.md)。

以下为基于源码的方案，尚未实现，也不是时间承诺。当前只基于已有研究街、收藏、场景实验和小镇搭建器判断价值。

## 1. 街区任务循环

最小流程：访问三个地点并收集资料 → 记录进度 → 获得称号/纪念卡 → 本机保存。

借鉴纯数据状态、有序事件、有界日志、结算与存档版本校验；保持现有三渲二场景。任务进度须来自真实操作，不用虚构项目填充。完成条件：刷新可恢复、重复点击不重复奖励、旧进度兼容、完成条件清楚。是否提高内容发现率需要另行测量。

## 2. 房间协作

最小方案：两位朋友共享街区任务进度，先同步交互事件，再考虑连续角色移动。

参考 Room 的创建/加入、房主权限、观众与断线宽限。小镇坐标、对象 ID、冲突裁定与权限需要自己实现；深井游戏坐标不能直接完成 Three.js 联机。完成条件：两台真实设备状态一致、操作不重复领取、断线与服务器重启行为明确。未部署。

## 3. 模型 NPC 实验

把“可达平台”替换为“可访问地点”，把“生命/背包”替换为“行动预算/任务资源”。模型选目标，本地执行导航与交互，事件反馈结果。先用结构化状态，再把视觉观察作为对照变量。

| 层 | 可参考的经验 | 小镇需提供 |
| --- | --- | --- |
| 观察 | 只给相关状态与可选动作 | 地点、任务、资源、合法操作 |
| 决策 | 有界 JSON、短计划、人格与记忆 | 业务目标和动作 schema |
| 执行 | 快慢循环分离、过期目标检查 | 导航、交互与失败恢复 |
| 反馈 | 事件流、耗时、调用量 | 真实成功/失败原因 |
| 复盘 | 总结回写下次提示词 | 可评估的历史与记忆对照 |

完成条件：同一初始状态比较规则与模型，记录完成率、时间和 Token；关闭模型时基本流程稳定。会说话不能代替任务执行验证。

## 独立扩展 002

| 方向 | 最小改造 | 验证重点 |
| --- | --- | --- |
| 主题小游戏 | 自有角色、一个章节和奖励 | 素材来源、操作与触屏 |
| 关卡编辑器 | 种子、路线、平台密度、机关与 Boss 配置 | 可达性、非法配置与导入导出 |
| Agent 实验台 | 固定种子、统一执行器、记忆/视觉对照、结果导出 | 多局重复、预算、统计与失败记录 |
| 成长与故事 | 有版本的进度、解锁与成长 | 旧存档兼容、奖励与难度 |
| 公网活动房间 | 独立后端与数据持久化 | 延迟、负载、重启恢复与权限 |

结合当前项目，先做街区任务循环最集中、最容易验证。多人和模型 NPC 增加同步、服务与调用成本，其收益需要实验支持。
