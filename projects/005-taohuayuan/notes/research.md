# 桃源：能力、效果、底层原理与复用价值

研究日期：2026-10-11。上游：[JimLiu/taohuayuan](https://github.com/JimLiu/taohuayuan)；固定版本：[61567657a5cffd64461d8e00c5907540b733f8dc](https://github.com/JimLiu/taohuayuan/tree/61567657a5cffd64461d8e00c5907540b733f8dc)。源码链接均指向这个版本。

## 1. 能力是什么

它是一套围绕《桃花源记》编排的 Three.js 前端应用。场景、镜头、原文与录音已经对应好；替换文章仍需设计空间、编写章节与标注音频，现成应用没有任意文章自动生成世界的功能。

| 上游已有能力 | 读者得到的体验 |
| --- | --- |
| 真实三维世界 | 溪流、桃林、山洞、田野、村落、人物与动物 |
| 28 幕循文导览 | 镜头、原文、白话、朗读与环境随故事推进 |
| 十处景致与自由漫游 | 环顾、行走、双击移动、快速换景 |
| 内容解释 | 词语释义与景物关联原文 |
| 播放与体验控制 | 暂停、回看、跳转、慢读、画质、动态与截图 |

本地研究台新增三段直达入口和研究说明，核心三维效果来自上游。切换通过同源连接层调用导演，不把原版渲染代码宣称为本地原创。

## 2. 效果是什么

桃林的溪水倒影、花瓣、近景花叶与远山营造春日环境。山洞是真实几何通道，镜头压低到人的观看高度；暗部与狭窄视野建立期待。走向洞口时，曝光、视角和镜头位置变化，使田野与村落逐步展开。

核心是“文章的转折变成空间与镜头的转折”。“豁然开朗”入口开始仍在洞内，几秒后出现揭示；一张村落截图不能代表全过程。

人物和建筑带有体素或简化几何风格，自然景物保留较丰富细节；宣纸色界面、书法排版和山水层次让解释内容与场景相容。学习效果、停留时间和商业转化没有用户研究数据，不能由视觉吸引力直接推导。

## 3. 底层原理是什么

### 世界布局与程序化生成

[`world/layout.js`](https://github.com/JimLiu/taohuayuan/blob/61567657a5cffd64461d8e00c5907540b733f8dc/src/world/layout.js) 统一定义溪流、盆地、山洞和村落。地形、相机、人物落脚与碰撞共用空间规则，避免错位。高度场叠加噪声与区域规则形成山谷，村落由可复现的几何组合构建。

[`world/peach.js`](https://github.com/JimLiu/taohuayuan/blob/61567657a5cffd64461d8e00c5907540b733f8dc/src/world/peach.js) 使用固定种子与若干树模板，生成枝干、花朵和叶片。固定种子使布局稳定，便于镜头编排和截图对比；环境阵风等行为并不因此全部逐帧确定。

### 渲染与材质

Three.js 基于 WebGL 2 实时渲染。着色器表现风、花瓣、水流、雾与程序化表面；Neutral 色调映射保持颜色关系。水面采用平面反射：镜像相机渲染到纹理，再结合波纹与视角相关的反射强度显示。见 [`world/water.js`](https://github.com/JimLiu/taohuayuan/blob/61567657a5cffd64461d8e00c5907540b733f8dc/src/world/water.js) 和 [`core/shared.js`](https://github.com/JimLiu/taohuayuan/blob/61567657a5cffd64461d8e00c5907540b733f8dc/src/core/shared.js)。

### 统一叙事时间线

[`story/chapters.js`](https://github.com/JimLiu/taohuayuan/blob/61567657a5cffd64461d8e00c5907540b733f8dc/src/story/chapters.js) 定义原文、白话、镜头函数、昼夜、船与风。[`story/director.js`](https://github.com/JimLiu/taohuayuan/blob/61567657a5cffd64461d8e00c5907540b733f8dc/src/story/director.js) 按章号与进度恢复主要叙事状态，控制顺播、跳转、暂停和慢读。

```mermaid
flowchart LR
  A[章节与音频时间标注] --> B[统一故事时钟]
  B --> C[章号与幕内进度]
  C --> D[镜头 / 字幕 / 光照 / 船]
  E[世界布局与程序化几何] --> F[Three.js 实时渲染]
  D --> F
  F --> G[浏览器交互体验]
```

镜头由插值与路径函数推进，相邻幕混合位置、方向与视角，远距离跳转用纸色转场遮住切换。“开朗”同时变化位置、方向、视野与曝光，形成从暗部走向开阔地的观看过程。

朗读是预录音频，字幕由时间标注驱动。录音播放时故事时钟校准到音频时间；被浏览器拦截时允许静音继续，用户交互后再从当前位置接入。运行时没有大模型生成或实时 TTS。

### 性能取舍

近树显示花朵细节，远树使用简化枝干与花冠片；重复物件实例化，建筑合并几何。镜头位于溪谷或盆地时隐藏另一侧区域；反射使用较低分辨率，根据帧率调整像素比。模型 gzip、图像 WebP、音频 AAC 减少体积。

这些是源码中的策略，不代表所有手机能达到某个帧率。本次未做真实手机基准。见 [`main.js`](https://github.com/JimLiu/taohuayuan/blob/61567657a5cffd64461d8e00c5907540b733f8dc/src/main.js)。

## 4. 使用场景是什么

以下是基于实现的应用判断，未做商业效果验证。

| 场景 | 可复用基础 | 仍需补充 |
| --- | --- | --- |
| 古文、诗词教学 | 原文、白话、朗读、暂停与回看 | 教学问题与学习评估 |
| 文化故事与数字展览 | 场景、镜头、热点与音景 | 策展、史料校对、授权 |
| 文旅或品牌导览 | 自由探索与路线叙事 | 地点/商品信息与内容管理 |
| 研究成果、作品集 | 分章介绍、空间入口与解释 | 检索、可访问性与常规阅读 |

适合故事明确、路线可编排、规模可控的体验。账号、云端进度、多人同步、完整任务系统和后台编辑不在当前能力范围内。

## 5. 可扩展方向是什么

1. 抽出章节、镜头、字幕与热点协议，建立通用导览播放器；先用短篇、三个场景验证配置是否够用。
2. 为现有小镇搭建器增加镜头点与参观路线，让搭建成果可以讲解内容。
3. 教育场景加入问题和进度，分别验证内容正确性与体验。
4. AI 辅助提出章节与镜头草案，再人工校对、编辑与验证可达性。当前没有实现。

上游 [`docs/prompt.md`](https://github.com/JimLiu/taohuayuan/blob/61567657a5cffd64461d8e00c5907540b733f8dc/docs/prompt.md) 提供制作要求。可借鉴的是把文章、空间、镜头、细节优先级和验收条件一起描述的方法，不能认定任意作品都能自动取得同等质量。

## 6. 对当前研究集的价值是什么

001 已有三渲二研究街、资料入口与小镇搭建器；桃源补充“如何组织观看与讲解”的经验。后续已将这一方法用于一分钟路线：街口看效果、商店找资料、阅读亭回看收藏，见 [001 导览记录](../../001-sakura-crossing/notes/tour.md)。

导览沿用 001 的美术风格，在本地重新编写时间线与镜头，没有复制桃源世界或源码。读者是否因此更好地理解内容，仍需用户研究验证；搭建器的路线编辑尚未实施。
