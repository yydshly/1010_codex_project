# 初版实验与实际验证

此文件保留首阶段结果。当前已加入原库本机体验与 BVH 第一人称漫游，最新进展见 [漫游升级记录](walk-upgrade.md)。

日期：2026-10-11。固定上游 `8cc20593b2270e2ce832e7b7b44356705daddec4`。本实验复用四个 MIT 算法模块，原创街巷、车辆、招牌、纹理和水花图集，独立编写简化水珠材质。完整上游城市与素材没有运行复现。

- 生产预览页实际启动 WebGPU，切换湿地视角、关闭反射成功；所捕获控制台没有 warn / error。
- 根目录 `npm.cmd run catalog:sync` 与 `npm.cmd run check` 均通过：12 个项目的编号、目录、图片与生成 README 一致。根检查不作为 GPU 功能测试。
- 生产主页中的两个相对路径 JS、CSS 和笔记下载请求均返回 HTTP 200；尚未进行公开部署。

早期 Vite 6 安装因网络连接重置未完成，后改用可获取的 Vite 8.3.4 完成安装。默认候选生产端口 5193 已被其他应用占用，最终使用空闲的 5194，没有关闭其他应用。

## GPU 碰撞回读实验

`web/verification.html` 是可重复运行的检查入口。`src/verify.js` 创建平地和顶面高 3.1 的 4 × 4 雨棚；在 8 × 8 雨区分配 1000 个粒子，以 1/60 秒步长连续计算 240 次。每一轮回读 GPU 位置缓冲与中心高度纹理。

以雨棚内部 |X|、|Z| < 1.6 的粒子作为采样，避免边缘离散采样误差。检查不是模拟返回值，也没有从 JavaScript 保存的粒子副本判断。

| 状态 | 中心高度 | 内部粒子数 | Y < 3.0 粒子数 | 结果 |
| --- | --- | --- | --- | --- |
| 加入雨棚 | 3.100 | 25 | 0 | 通过 |
| 移除雨棚 | 0.000 | 33 | 5 | 通过，负对照证明粒子可继续落到棚下 |
| 恢复雨棚 | 3.100 | 24 | 0 | 通过 |

原始回读记录：[gpu-verification.json](gpu-verification.json)。计数会随运行种子和时间变化。该结果支持简化场景中的最高面碰撞与高度更新，不能证明完整城市、多层空间、快速摄像机移动或任意设备全部正确。

## 实验中修复的问题

1. 初始相机曾落在建筑范围内，遮挡画面。调整街巷与导览路径后，街道和车辆清晰可见。
2. 雨棚整块发光过强。保留金属顶面，改为细条霓虹边框，方便观察落雨与遮挡。
3. 高度图最初使用 180 像素宽，GPU 回读行对齐后出现条纹。改为 192 像素、RGBA8 每行 768 字节，满足 256 字节对齐，重新观察到正确的建筑轮廓。
4. 雨粒子的原始固定帧速度改为 delta 积分；再生 Y 参考新 XZ 的碰撞高度，避免高楼上方生成不足。

## 已知边界与待验证项

- WebGL2 兼容后端尚未实测；当前主要验证 WebGPU。
- 三维渲染要求 localhost 或 HTTPS 可信上下文。启动失败时仍保留中文技术说明。
- 每列只保存一个最高面；多层道路、洞内雨、墙面风雨与真实水体需要扩展。
- 水花独立循环；涟漪不与每个雨滴碰撞事件配对。
- 滑块只调可见雨丝和水花实例数，GPU 缓冲与计算保持 5000 的分配上限。
- 未测试上游完整漫游、视频、音效、GTAO 和玻璃开场。
- 未进行跨设备性能、真实触控和公开部署验证。
