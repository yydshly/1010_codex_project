## 完整摘要：能力、模块、原理、场景、价值与扩展

### 能力：两种视觉世界，以及已经跑通的探索

固定版本是一套 Three.js / WebGPU / TSL 场景工程。源库组合 GPU 雨丝、水花、屋顶遮雨、路面反射与涟漪、车漆滑落水珠、玻璃雨开场、霓虹后处理和第一人称 BVH 探索；它的直接能力是实时呈现场景并允许观察和交互。

完整城市的效果还依赖模型、车辆、视频招牌、烟雾、飞行器、环境光、GTAO、Bloom、雾、统一色调与空间音效。单独的下雨算法只负责其中一层；城市丰富度与艺术设计不能由一个粒子模块自动替代。

上游用代码生成日式街区、建筑、招牌和道具，结合球形世界、步行/奔跑、地形碰撞、骑行、列车与铁路道口、店门及环境动画。上游构建和加载已验证，完整漫游与骑行未实测。

本地已把风格保留到研究街、商业街/林间村落/小广场、小镇搭建器、中文语音镜头导览和晴雨第一人称漫游；内容阅读收藏、物件编辑与 JSON 存档已有实际操作记录。

另有 AI 守灯游戏与真实 OpenAI/MiniMax 策略实验。模型调用由本机服务处理；静态网页展示资料和证据，云端模型游戏尚未部署。

### 模块：渲染、环境、交互与业务分别负责什么

九组逻辑职责是：启动与宿主循环、场景/模型/灯光、相机与 BVH 控制、高度纹理、GPU 雨滴/水花、湿地镜像/雨纹、表面水珠、后处理与设备预算、DOM 说明/操作桥。它们是源码职责分组，不能把每一组都视为已发布的通用包。

渲染层：分段光照、冷紫暗部、深度描线、重点物件外壳描边、调色、色彩转换和抗锯齿；场景层：建筑、树木、道路、招牌、灯光与可复现布局配置。

Rain Kit 已提取 createWeather、createWetGround、createDropletMaterial、createWalkControls / buildModelBvh。四项各有宿主输入、参数、更新、开关与 dispose；同一实现用于原创研究台、独立最小消费者和樱花街接入。

交互层：地点 ID → 内容/动作，店门、阅读收藏、可编辑物件、撤销重做、本机存档和导入导出；导览层：语音时间统一驱动镜头、字幕与地点动作。

宿主提供 scene、初始化后的 WebGPURenderer、camera、canvas、UV、地面和碰撞代理；模块管理自己的雨缓冲、渲染目标与材质。借用的贴图默认不释放，宿主共享几何/BVH/renderer 由宿主管理。

城市素材、固定中文面板、模型服务、内容收藏、故事和玩法不在 Rain Kit 中。樱花街只接入天气、湿地和漫游三项；水珠仍在最小例子中体验，风格与导览也尚未独立成通用包。

### 原理：从 GPU 雨夜，到动画风格与受约束行动

Three.js 管理场景、几何、相机、纹理和资源；TSL 以 JavaScript 节点描述材质与计算，由节点系统生成 GPU 程序；WebGPU 执行渲染与计算。中文 DOM 面板改变真实参数，不绘制三维效果。

降雨先用俯视正交相机把最高表面的世界位置写入半浮点高度纹理。GPU 用雨滴 XZ 查对应 Y，移动粒子、比较表面并重生，再用面向镜头的实例平面批量画雨线。delta 积分降低帧率带来的速度差；水花独立周期，并非每颗粒子碰撞事件驱动。

湿地通过镜像相机额外渲染场景，隐藏地面并使用斜裁剪，按粗糙度与强度混合反射。程序雨纹扰动法线和采样 UV；水珠则由掩码有限差分改变法线/粗糙度，影响高光。Rain Kit 水珠为独立原创椭圆图案，不复制原复杂拖尾或玻璃折射。

BVH 加速静态几何射线，控制器处理步行、蹲下、地面与墙体滑行。循环顺序为相机输入 → 高度/GPU雨 → 材质时间 → 世界矩阵 → 镜像 → 主渲染/后处理。高度图只保留最高面，镜像只按平面实现，漫游不是刚体引擎。

基础几何与 Canvas 纹理生成形体 → 量化光照色阶 → 场景颜色/深度 → 深度二阶差分描线 → 冷暖调色及 linear→sRGB → FXAA。造型、构图、材质和灯光共同决定三渲二观感。

上游先在 XZ 平面组织世界，再映射到半径 160 米球面；可见地形、高度与碰撞查询必须一致。扩展街景按组件和配置组织，可独立复用渲染方法。

AI 只提出有限策略，Schema 与时效校验后由本地规则和连续控制执行；实时绘制、碰撞、状态与胜负由引擎负责。中文导览则用本地音频 currentTime 统一驱动镜头、字幕和店门，暂停与回看使用同一时间线。

## 1. 我们的核心理解

场景负责表达内容，模块负责重复使用的能力。现在已经把雨夜项目的天气、湿地反射和漫游装进樱花小街，保留了它原有的动画风格。下一次可以继续替换场景、材质和业务内容。

### 这个库的价值，就是构建这种场景吗？

具体场景是技术的载体。Sakura 留下场景组件、视觉管线和地点交互；雨夜项目留下 GPU 天气、湿地反射、材质和漫游机制。已经做出的跨项目接入证明它们能用于不同美术风格。对你最直接的价值，是下一次做展厅、研究地图或小型探索体验时，沿用已验证的能力与接入方法。

### 复用的是这里的下雨吗？

包括下雨，也包括湿地倒影、水珠材质和漫游。樱花街本次实际接入天气、湿地和漫游三部分；水珠保留在模块最小示例与雨夜场景中。樱花街的建筑、粉樱、色阶、描线和业务内容仍由自己提供。

### 原库效果为什么比最小示例丰富？

完整城市把模型、贴图、灯牌、视频、音效、灯光、雾、材质与后处理组合在一起。最小示例的任务是明确一个模块怎样接入和释放。要达到原城市的美术质量，仍需要内容资产、视觉设计、材质适配和性能预算。

### 能把模块直接装到任何 Three.js 项目吗？

当前包固定 Three.js r185，天气、湿地与水珠采用 WebGPU / TSL 节点渲染；宿主需要已初始化的节点渲染器。樱花街增加材质和后处理适配后才接通。单纯使用 WebGLRenderer 的旧项目需要迁移或做专门兼容层，不能保证直接调用即可。

### 能用来做哪些产品？

已经可体验研究资料街、编辑搭建器、中文自动导览、晴雨探索与 AI 守灯游戏。可继续扩展品牌展厅、课程与文化探索、专注庭院或多人活动；每个方向都需要补齐自己的用户流程、数据与验证，场景不能自动提供完整业务能力。

### 是否能够自动生成任意新世界？

现有组件和配置能生成预设范围内的布局。搭建器支持固定对象编辑；AI 小镇使用模型选择允许的策略。目前没有从一句话任意生成模型、地形和可玩规则的生产系统。可以先定义可校验的组件配置，再加入受约束的 AI 布局生成。

### 性能数据应怎样理解？

旧场景采样记录的是指定浏览器、画面尺寸与构建版本的帧间隔、CPU 提交和绘制计数，不能推断所有设备。GPU 雨滴能把计算放到 GPU，反射却会增加一遍场景渲染。需要以目标设备、分辨率、容量、反射频率和真实内容选择预算。

### 接下来最值得扩展的方向是什么？

先把宿主接入层和视觉预设整理稳定，补真机与长时性能验证；再做可配置场景、地点内容协议和受约束的 AI 编辑。多层遮雨、动态碰撞、通用风格包、云存档与多人属于后续独立工程，按真实需求推进。

## 3. 真实效果对照

### 晴天 / 雨天

天气可以改变，街道的视觉语言继续保留。

相同几何与观察视角。雨天启用雨滴、涟漪和湿地，稍微调整光照与雾；樱花、色阶、描线和招牌共用原实现。动画帧中的花瓣与雨滴位置会变化。

截图类型：同视角场景实拍。晴天 · 干燥路面 / 雨天 · 雨线、涟漪、湿地。

### 湿地反射

倒影来自第二台镜像相机。

反射会增加一次场景渲染。路面法线、粗糙度与涟漪改变清晰度和扭曲程度。观察镜头移动时倒影的视差，再调整强度。

截图类型：原创雨夜研究台实拍。关闭平面反射 / 开启平面反射。

### 物体水珠

水珠主要改变表面的法线与粗糙度。

独立模块在 UV 上生成椭圆水珠，用高度变化近似法线，形成湿润的反光。它没有复制原库带授权限制的水珠 shader，也没有实现镜头水珠或真实水滴流体。

截图类型：独立模块最小场景实拍。关闭水珠细节 / 开启模块水珠。

### 霓虹辉光

明亮像素扩散，让灯牌产生柔和光晕。

辉光是整幅画面的后处理。原库效果同时依赖灯牌、材质、雾、曝光和调色；这组截图用于观察总体差异，原城市实时面板可以保持相同视角逐项切换。

截图类型：原库完整城市实拍 / 不同截图帧。关闭辉光 / 完整雨夜效果。

### 动画描线

少量线条，让三维形体更接近动画。

最小三渲二实验。深度纹理的二阶差分发现边缘，几何外壳补充轮廓，调色统一冷暖关系。线宽、近远距离与材质形状都会影响效果。

截图类型：早期最小三渲二实验实拍。关闭描线 / 描线与调色开启。

## 4. 技术底层与可复用价值

更新顺序：宿主场景与输入 → 相机和世界矩阵 → 高度图 / GPU 雨滴 → 材质时间与镜像反射 → 宿主最终渲染。观察与漫游控制器互斥。

### 场景与内容

**几何与配置构成空间，稳定地点 ID 连接业务。**

计算路径：GEOMETRY → PLACE → ACTION

1. 组件根据位置、尺寸、朝向和配色生成房屋、树木、道路。
2. 固定随机种子让相同配置生成相同布局；重复静态部件使用实例化降低绘制调用。
3. 地点按钮与三维命中共用动作：开门、阅读、收藏、跳转或编辑。
4. 本机收藏与搭建器存档保存在浏览器；账号、后台与跨设备同步需要另行接入。

观察方法：把场景当作内容地图：商店读资料，阅读亭回看。搭建器证明组件能从展示进入编辑流程。

复用价值：可以复用视觉风格、组件和地点交互，再替换成项目、产品、课程或展览数据。业务价值最终要靠真实访问与任务完成验证。

边界与成本：当前地点业务尚未统一成跨项目动作包；搭建器只提供三个固定组件，不自动连接路网或处理重叠。

详见：[研究街 · 阅读与收藏流程](../../001-sakura-crossing/notes/business.md)。

### 三渲二风格

**分段光照、冷色暗部、轮廓与调色共同形成动画感。**

计算路径：LIGHT → BANDS → INK → COLOUR

1. toon 渐变贴图用最近邻采样，把连续光照压成少量明暗色阶。
2. 暖色太阳、冷色补光和半球光组织亮暗关系，暗部加入冷紫染色。
3. 反向外壳描边补轮廓；屏幕空间深度二阶差分找出几何边缘，并按远近衰减。
4. 后处理做暗部冷色、高光暖色、饱和度、暗角和抗锯齿；输出保持线性色彩到 sRGB 的正确顺序。
5. 樱花晴雨页用节点材质与 TSL 适配原风格；其他早期页面继续使用 WebGL 管线。

观察方法：在技术实验里只关闭描线，再只关闭调色；比较线条与配色各自的作用。

复用价值：统一新模型、不同布局与页面的视觉语言；保留可调参数，比每个场景重新手调更易维护。

边界与成本：材质适配仍是项目代码，尚未打成独立风格包；导入新模型要核对法线、UV、透明与配色。

详见：[Sakura · 三渲二与上游研究](../../001-sakura-crossing/notes/research.md)。

### GPU 雨滴与遮雨

**俯视高度图给雨滴一个可查询的落地高度。**

计算路径：HEIGHT MAP → COMPUTE → INSTANCES

1. 正交相机从上往下渲染场景，纹理记录 XZ 位置上的最高表面世界 Y 值。
2. GPU 存储缓冲保留每滴雨的位置与速度；计算节点按 delta 更新下落和风向。
3. 雨滴用 XZ 坐标采样高度图，到达表面后重生，避免穿过已记录的屋顶。
4. 实例化面片朝向镜头绘制雨线；地面水花和涟漪独立循环，不是一滴雨一次真实碰撞事件。
5. 天空、湿地和碰撞代理从高度图中排除；关闭天气停止高度更新与雨滴计算。

观察方法：站在商店屋檐下，再去 GPU 验证页移除屋顶。比较高度值和雨滴位置，能直接验证遮雨机制。

复用价值：沿用粒子计算与高度查询，只给新项目自己的场景、相机和覆盖范围，即可接入天气。

边界与成本：这是 2.5D 最高表面近似；多层建筑、横向挡雨和复杂洞穴要扩展。固定容量分配与计算，可见数量降低不等于计算量同比降低。

详见：[模块提取、独立安装与 GPU 验证](../references/012-threejs-conference/notes/module-extraction.md)。

### 湿地与平面反射

**镜像相机再看一次场景，地面采样它的画面。**

计算路径：MIRROR CAMERA → TARGET → WET MATERIAL

1. 按地面平面镜像主相机，使用斜裁剪平面过滤不应该出现在倒影中的内容。
2. 隐藏反射地面，渲染到离屏纹理，避免地面反射自身；结束后恢复渲染器与场景状态。
3. 把纹理投影到路面，用法线和涟漪扭曲采样坐标，粗糙度控制混合。
4. 半分辨率、隔帧更新降低额外渲染成本；移动时可能看到轻微滞后。
5. 樱花街只覆盖道路，保留原人行道、路沿与标线；强度、雨滴与涟漪分别可控。

观察方法：切雨天后关闭雨滴、保留湿地；移动镜头，观察倒影随视角变化，再把反射强度调到零。

复用价值：可用于雨街、水面、展厅光洁地面等大体平坦表面，宿主继续控制场景与风格。

边界与成本：平面倒影不适用于任意弯曲表面，也不是通用光线追踪；当前反射混合带发光分量，不是完整能量守恒材质。

详见：[跨项目晴雨接入 · 完整笔记](../../001-sakura-crossing/notes/weather-reuse.md)。

### 物体水珠材质

**通过材质细节表达湿润，不增加大量水滴几何。**

计算路径：UV HEIGHT → NORMAL → ROUGHNESS

1. 在带 UV 的物体表面，按哈希分布与周期生成椭圆水珠高度。
2. 对高度做有限差分，得到局部法线扰动，改变反射方向和高光。
3. 同步调整粗糙度，让干燥与湿润区域有不同反光；速度与数量是可调参数。
4. 模块返回新的 MeshPhysicalNodeMaterial，宿主决定用在哪个模型，保留自身材质风格。
5. 原库水珠效果有独立授权来源；本地模块使用重新编写的近似算法。

观察方法：最小场景中比较同一物体的水珠开关；原完整城市可观察汽车车身和玻璃。两套实现视觉细节不同。

复用价值：可给车辆、窗户、道具增加可控制的湿润表现；与天气开关连接，组成统一雨天状态。

边界与成本：需要正确 UV；没有原库流淌轨迹、镜头水珠、真实流体与自动玻璃折射。樱花街本次没有接入水珠材质，以免改变原风格。

详见：[Rain Kit · 完整中文 API](../references/012-threejs-conference/web/modules/rain-kit/API.md)。

### 第一人称漫游

**输入决定运动，地面与碰撞把镜头约束在可走空间。**

计算路径：INPUT → GROUND → BVH → CAMERA

1. WASD、方向键与屏幕按钮控制移动；拖动转头，鼠标锁定作为可选增强。
2. 控制器管理加减速、行走、快走、蹲下、眼高和视角。
3. 地面探测决定脚下高度，允许小台阶；静态碰撞代理的 BVH 加速墙体查询。
4. 宿主提供真实地面和简化墙体代理；复杂透明招牌或装饰不应直接变成不可走障碍。
5. 观察与漫游控制互斥；失焦清输入，卸载移除事件和拥有的资源。

观察方法：进入樱花街商店屋檐，朝墙走会停住；按 C 蹲下、Esc 回观察。屏幕方向按钮也可行走。

复用价值：为研究街、展馆、培训、探索游戏共用人的尺度和基本行走；地图位置与业务热点继续由宿主管理。

边界与成本：静态 BVH 和地面射线，不是完整刚体物理；移动模型要更新碰撞数据。没有通用跳跃、攀爬与多层导航系统。

详见：[跨项目晴雨接入 · 完整笔记](../../001-sakura-crossing/notes/weather-reuse.md)。

### 辉光、遮蔽与气氛

**后处理负责画面整体气氛，和材质、灯光一起工作。**

计算路径：HDR SCENE → POSTPROCESS → DISPLAY

1. 发光灯牌与明亮高光先形成 HDR 场景颜色。
2. Bloom 提取明亮区域并模糊合成，产生光晕；GTAO 增强接触处与凹部的遮蔽。
3. 雾、曝光、对比、冷暖调色与暗角统一雨夜气氛，最后输出到显示色彩空间。
4. 原城市还依赖完整建筑、贴图、音视频招牌、烟雾等内容；算法开关不能替代美术制作。

观察方法：原场景把四项效果全关，再单独打开辉光或反射。保持同一视角最容易区分每项贡献。

复用价值：保留一套可控气氛预设，用于展览、创意主页、数字场景与视觉研究；参数要适配设备预算和内容。

边界与成本：辉光、GTAO、原城市音视频未进入 Rain Kit 四模块包；樱花街保持自己的调色，不直接搬入霓虹雨夜风格。

详见：[雨夜原库 · 能力、原理与价值](../references/012-threejs-conference/notes/research.md)。

### 导览与时间轴

**一个时间源，让讲解、镜头和地点动作保持一致。**

计算路径：AUDIO CLOCK → CAMERA → SUBTITLE → ACTION

1. 三段中文脚本先生成本地音频；播放时不再请求语音服务。
2. 音频时间驱动相机插值、章节字幕和店门开关。
3. 暂停、定位和恢复都回到同一时间轴；自由探索时把镜头交还用户。
4. 静音与文字字幕保留完整内容入口，浏览器音频由用户点击启动。

观察方法：暂停、拖到商店章节、再播放，检查讲解与镜头是否一起改变。

复用价值：复用于自动展览、产品演示、文化导览与教学片段；替换脚本、地点和路径即可形成新的叙事。

边界与成本：当前脚本与镜头控制仍是樱花街实现，尚未独立打包；真实移动端音频与触屏行为仍需目标设备测试。

详见：[中文导览 · 语音、字幕与镜头](../../001-sakura-crossing/notes/tour.md)。

### AI 策略与规则世界

**模型提出有限策略，确定性规则决定能否执行和结果。**

计算路径：STATE → MODEL JSON → VALIDATE → RULES

1. 本机服务提供最近状态、行动历史、油料、灯光、天气和玩家指令。
2. 一次结构化响应包含敌人、教练、队友、NPC 和场景导演五类策略；它不是五个独立后端代理。
3. 服务端校验 JSON、允许动作、目标地点、资源与时效，拒绝无法执行的命令。
4. 10 Hz 规则循环执行移动、寻路、点灯和胜负；模型调用慢或失败时，已有有效策略继续运行。
5. 45 秒周期请求、单请求在途、冷却和状态过期控制避免无限调用；页面隐藏暂停。

观察方法：规则模式体验固定分工；在已配置模型的本机服务上观察决策日志与角色实际行为。这里不会替你自动发起模型调用。

复用价值：让角色和环境策略可调整，同时保持可解释的状态、可重复规则和明确失败边界；能扩展到教学 NPC 或游戏导演。

边界与成本：模型不生成任意建筑或技能，也不直接改背包和胜负。真实调用速度与有效率依赖模型；已有记录不能保证每次局面都能完成。

详见：[AI 守灯夜 · 策略与规则架构](../../001-sakura-crossing/notes/ai-town.md)。

| Rain Kit | 天气计算、湿地反射、水珠节点材质、行走输入与碰撞查询 | createWeather / createWetGround / createDropletMaterial / createWalkControls + buildModelBvh | Three.js r185 节点渲染；新场景传入依赖并按约定更新、释放 |
| 渲染与风格适配 | 初始化渲染器、toon 节点材质、描线、调色、最终输出 | 樱花天气页已验证 WebGPU 适配；WebGL 旧页面保留独立入口 | WebGLRenderer 不能直接挂上节点天气材质；适配不等于改一个开关 |
| 产品与服务 | 阅读、收藏、编辑存档、语音导览、AI 策略与真实业务接口 | 稳定地点 ID、可校验数据、规则执行层与服务端边界 | 账号、云存档、支付、多人、分析与发布均需按新业务建设 |

### 天气

`await createWeather({ scene, renderer, camera, capacity, count, height, rain })`

配置：初始化完成的 WebGPURenderer；覆盖范围、高度相机、分辨率、更新间隔与排除对象；固定容量 500–5000。

接口：update(delta) · setEnabled · setIntensity · setDropCount · dispose

宿主提供：场景几何与矩阵、高度覆盖区域、相机与天气状态

成本：容量决定分配与计算；setDropCount 改可见数量，强度主要控制视觉透明度。

### 湿地

`createWetGround({ scene, y, textures, reflectionStrength, resolutionScale, frameSkip })`

配置：平面位置和缩放、颜色/法线/粗糙度、倒影分辨率与隔帧频率；参数完整定义见包 API。

接口：update(delta) · updateReflection(renderer, camera) · setEnabled · setReflectionStrength · setRippleAmount · dispose

宿主提供：要变湿的地面、纹理、场景、主相机与风格匹配

成本：额外渲染一次反射场景；半分辨率与隔帧减少成本。

### 水珠

`createDropletMaterial({ color, amount, speed, normalStrength, roughness })`

配置：物理节点材质；几何需 UV，可选择 UV 集，水珠量、速度与法线扰动。

接口：material · update(delta) · setAmount · dispose

宿主提供：用材质的物体、正确 UV、原风格的材质替换策略

成本：增加片元材质计算；不是增加真实液体模拟。

### 漫游

`buildModelBvh(root) + createWalkControls({ camera, domElement, model, ground, colliders })`

配置：透视相机、可聚焦画布、静态碰撞与地面；眼高、速度、半径、台阶与蹲下。

接口：update(delta) · setActive · setMoveAxes · clearInput · syncEulerFromCamera · snapCameraToGround · dispose

宿主提供：可走区域、碰撞代理、出生点、地面与观察/行走模式切换

成本：静态 BVH 加速查询；几何改变需要重建或更新碰撞数据。

### 接入步骤

1. 安装本地 @research/rain-kit 0.1.0 tgz，并固定 Three.js 0.185.1 与 three-mesh-bvh 0.9.13。此包没有发布到公共 npm。
2. 初始化 WebGPURenderer 和主相机，先确保原场景可以正常显示；给 WebGL 项目补节点材质与风格适配。
3. 传入场景与相机创建天气，明确高度图覆盖与排除对象；用新场景屋顶检查遮雨。
4. 只在需要的平面上创建湿地，设置位置、尺寸、纹理和反射成本；水珠按物体单独选择。
5. 给漫游传入地面和简化静态碰撞代理，验证眼高、墙体、台阶、蹲下和屏幕按钮。
6. 每帧先更新场景和相机矩阵，再更新天气/材质、反射和最终输出；观察与漫游控制互斥。
7. 卸载先停止循环，再 dispose 模块与宿主拥有的资源；测试释放与重新挂载，最后做目标设备和生产路径验证。

最小宿主、完整参数、源码出处：[Rain Kit · 接入示例与生命周期](../references/012-threejs-conference/web/modules/rain-kit/README.md)、[Rain Kit · 完整中文 API](../references/012-threejs-conference/web/modules/rain-kit/API.md)、[Rain Kit · 代码出处与授权](../references/012-threejs-conference/web/modules/rain-kit/PROVENANCE.md)。

@research/rain-kit 0.1.0 为 private / UNLICENSED 的本地研究包，没有发布到公共 npm。固定 Three.js 0.185.1 / three-mesh-bvh 0.9.13；天气与节点材质需要节点渲染器，传统 WebGLRenderer 项目要先适配。
