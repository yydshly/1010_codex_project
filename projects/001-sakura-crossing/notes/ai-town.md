# 樱街守灯夜：把场景变成可玩的 AI 小镇

这是第一个项目的本地玩法扩展，沿用樱花小街的程序化建筑、树木与三渲二渲染思路。新玩法、角色和物资规则为本研究原创，不复刻上游游戏，也未引入外部人物模型。

## 为什么换成这个方向

模型决策往往需要十几秒，适合分工、角色对话和场景节奏调整。守灯小镇把这一时间尺度变成可理解的协作过程：玩家实时走动，居民执行上一轮策略，模型根据观察安排下一阶段。

目标是点亮西街、广场、东街三盏灯，同时守住 20 秒。玩家有 240 秒，按 E 点灯或领油，按 Q 驱散纸灵。花灯需要一份油和 2.2 秒实际点灯动作。角色携带的油、杂货铺总库存、纸灵偷油、巡街阻挡都由同一套游戏规则计算。

## 五种 AI 角色

| 角色 | 模型决定 | 游戏中的结果 |
| --- | --- | --- |
| 敌方指挥 | 纸灵去西街、广场或东街；偷油、干扰或退却 | 纸灵移动、盘旋、偷油，被守卫或摇铃驱散 |
| 玩家教练 | 下一步地点与一句行动建议 | 金色目标圈与行动提示，玩家自行执行 |
| 队友阿澄 | 点灯、领油、守灯、跟随、等待 | 实际走路、领取物资、耗油点灯或跟随玩家 |
| NPC 柚子与晴 | 有身份的台词和同一组受限动作 | 店主可离店帮忙，巡街人可换防，两者也可点灯 |
| 场景导演 | 平静、阵风、薄雾、萤火与持续时间 | 移动速度、灯油流失、雾、萤火粒子发生变化 |

这些角色由同一轮模型输出协调，不是五个独立后台智能体。居民的短期记忆包含当前状态、最近行动和最近两轮分工；没有跨局持久记忆。

## 模型接入与执行边界

浏览器请求本机 Node 服务，服务通过官方 Codex CLI 的 app-server 使用已登录账户。CLI 管理认证，代码不提取 OAuth token。界面显示实际返回的模型名；不把默认模型冒充其他产品型号。MiniMax 可读取用户此前授权的本机配置路径，密钥只在服务端，失败不会伪装成真实模型。

模型获得玩家最近 15 秒位置采样、最近行动、各角色油量、花灯状态、天气和玩家命令，返回受 JSON Schema 约束的策略。服务端再次验证任务与地点组合。模型不能直接执行代码、改变库存数字、读取文件或调用游戏外工具。执行器以 10Hz 推进路径与规则，浏览器显示动作。

首轮分工在准备画面完成，点击「进入小镇」才开始计时。战斗中每 45 秒再观察一次，也可通过对话主动请求。每局最多 10 轮，同局单请求，主动命令间隔至少 10 秒，50 秒超时，观察超过 35 秒弃用。模型错误会显示，已有策略继续执行。离开标签页自动暂停；回到标签页继续。

普通规则模式采用固定分工、固定西街纸灵目标和平静天气，不能理解自然语言。两种模式使用相同角色移动、物资、点灯和胜负规则。

## 运行

在 `web/` 执行：

```powershell
npm.cmd run build
npm.cmd run game
```

默认地址为 `http://127.0.0.1:5197/game.html`。服务仅监听本机。通过 `TOWN_PORT` 可改端口；`TOWN_CODEX_CLI` 可指定官方 CLI 入口，默认使用本机 npm 安装位置。MiniMax 默认读取 `F:/codex_project/.env.minimax`，可通过 `TOWN_MINIMAX_ENV` 指定。没有部署到公网。

原研究页面可以通过游戏左上角返回；Vite 的普通 `dev`/`preview` 不提供游戏模型 API，完整游戏请使用上面的本机服务。

## 验证与当前限制

`npm.cmd run test:game` 检查房屋避障、玩家耗油点灯、队友补给后返回、跟随、居民点灯、纸灵偷油与守卫阻挡、摇铃冷却、天气影响、胜负和非法模型指令拒绝。模型实际请求和浏览器体验记录另存于本项目，而不把测试中的手工策略当成真实 AI 证据。

目前是单个本地场景与一条守灯任务，天气和角色动作来自预先实现的能力集合。模型没有现场生成任意 3D 模型、修改地形或创造任意技能。可继续扩展为支线委托、角色持久记忆、队伍关系和编辑器场景协议；先扩展可执行动作，再让模型选择，才能避免只生成文字。

### 2026-10-11 真实 OpenAI 局

[完整本局 JSON](ai-town-openai-session.json) 保留模型输入、原始输出、应用和实际角色动作。实际模型为 `gpt-5.6-sol`，官方 CLI 返回认证类型 `chatgpt`。首轮 18.032 秒，把玩家分配到广场、阿澄到西街、柚子到东街、晴守西街。

玩家走到西街并用自然语言改口。第二轮 16.209 秒，观察于 0.6 秒、应用于 16.89 秒：阿澄改跟随、柚子改修广场、晴改守东街、纸灵改攻东街、萤火持续 18 秒。执行记录显示柚子 23.2 秒点亮广场、晴 20.6 秒开始阻止东街纸灵，阿澄最终走到玩家附近。游戏于 43.097 秒实际获胜，三灯同时守住 20.014 秒。玩家这局主要通过分工完成目标，没有把 NPC 点灯冒充玩家亲自点灯。

[决策与获胜截图](../assets/ai-town-decisions.png) 为真实网页截图。验证说明中的模型延迟为本次实测，不能当成固定响应保证。

### 普通规则和玩家操作对照

[规则局 JSON](ai-town-rules-session.json) 为浏览器实际操作记录：WASD 的 D 键改变目标坐标，玩家点击西街后在 23.3 秒耗一份油点灯，21.3 秒摇铃驱散一只纸灵，72.9 秒到店领取两份油，最终油量为 3。发送“阿澄跟着我”后，规则模式保留东街固定职责、没有模型调用，显示无法理解自然语言。

最终构建通过；游戏 11 项规则与调度测试与原技术实验、搭建器、中文导览检查均通过。根 `npm.cmd run check` 通过 12 项目录与登记表校验。Three.js 打包体积提示仍存在，未将其当作运行失败；本次未做手机实机帧率基准。

### MiniMax 的实际边界与修复

[MiniMax 首轮及定时观察记录](ai-town-minimax-boundary.json)：`MiniMax-M2.7-highspeed` 首轮 17.3 秒通过验证并应用，阿澄实际点亮西街、晴阻止纸灵、柚子领取物资；玩家另行点亮东街。45.1 秒触发自动再观察，但该轮把领油任务配到非商店地点，执行器拒绝，现有策略继续运行。没有将这轮当成成功调整。

随后把合法的任务/地点组合写入 JSON Schema 的 `anyOf` 分支；完整原始输出会在验证前保存。模型返回了格式或指令错误时，允许一次带错误说明的纠正请求，读取新的状态、计入10轮额度；传输错误和超时不自动重复。纠正控制流使用模拟接口验证：错误拒绝→读取更新后的状态→应用合法结果；重复错误停止、并发阻止、额度阻止与网络错误不重试均通过。这些模拟接口结果不冒充真实模型证据。
