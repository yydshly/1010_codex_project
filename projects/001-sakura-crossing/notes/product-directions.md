# Sakura Crossing 能力理解与产品扩展

用统一的三渲二风格，把内容、任务和交互组织成可以探索的小世界。当前已验证场景展示、内容发现、配置实验和最小小镇搭建；游戏机制、云端分享与多人空间需要继续建设。

更新日期：2026-10-10。内容协议版本：1。

上游：[Sakura Crossing](https://github.com/Kenton-GMI/sakura-crossing)，固定版本 [de01898e89c7f6ab3fad93fa802f0f5ac66fbd81](https://github.com/Kenton-GMI/sakura-crossing/tree/de01898e89c7f6ab3fad93fa802f0f5ac66fbd81)。

上游源码 MIT；本地未引入上游音乐。新增模型、图片、字体与声音需分别记录授权。

本页区分上游研究、本地演示与后续产品方案。应用价值与推进顺序依据现有实现判断，商业效果尚未验证。

## 能力理解

**可复用的风格化场景展示与交互基础。** 房屋、树木和道路构成空间，地点承载内容或动作。换布局与业务内容，可以得到研究街、村落、展厅等体验；三渲二管线让它们保持相近的视觉语言。

- **配置组织空间：**场景配置决定组件的位置、尺寸、朝向与配色；固定随机种子使布局可复现。
- **组件生成形体：**几何体与招牌由代码生成；重复静态部件实例化，可开关的店门独立保留。
- **管线统一风格：**分段光照、冷色暗部、轮廓线、调色与抗锯齿共同形成动画感，模型形状与构图同样影响效果。
- **地点连接业务：**研究街用地点点击触发阅读和收藏。新增用途需要把地点 ID 接入对应内容、任务或服务。

## 产品价值

### 体验有辨识度

小世界可以形成统一视觉主题，让项目展示更容易被识别与记住；是否改善使用效果需要真实用户验证。

### 内容有空间关系

建筑与地点可以承载不同主题，通过探索组织内容；同时保留搜索、列表和直接链接，便于快速访问。

### 扩展有共同基础

场景组件、风格预设与测量方法可沿用到下一次实验，减少重复搭建；实际效率收益需在后续项目比较。

## 可扩展产品方向

### 研究小镇

内容与展示；优先探索；工程范围：中。已有内容流程，扩展方案待实现。

**目标用户：**研究者、开发者、个人作品集作者。

**用户问题：**项目笔记与演示分散，需要一个便于发现、阅读和持续扩充的入口。

图书馆放研究笔记，工坊打开技术实验，项目店铺展示能力与限制，阅读亭回看收藏。每新增一个研究项目，可以增加一个有明确入口的地点。

**用户流程：**找到项目地点 → 阅读能力与原理 → 打开实际演示 → 收藏并继续研究。

**现有基础：**三渲二渲染、共用场景组件、地点与开店交互、阅读与本机收藏。

**需要新增：**

- **多项目内容模型：**用稳定项目 ID 关联摘要、笔记、演示与地点，替换当前单项目三个章节的固定数据。
- **快速访问：**增加搜索、主题筛选、列表入口与可复制的项目链接。
- **持续维护：**记录阅读进度与内容版本；跨设备收藏需要账号与服务端同步。

**最小方案：**先接入两个真实研究项目，每个项目都有摘要、笔记和演示入口；同时提供地图与列表两种访问方式。

**完成条件：**

- 访客能找到指定项目并打开它的真实演示。
- 刷新后可以回到收藏的资料。
- 新增项目通过内容数据接入，无需改写渲染管线。

**适用条件：**知识管理的效率依赖搜索与内容质量；空间探索不应成为必经的阅读步骤。

关联视觉：[樱花商业街](../web/lab.html#street)。这是现有场景实验，不代表该产品已经实现。

### 三渲二小镇搭建器

创作工具；优先探索；工程范围：中高。本地最小搭建器已实现，约束与共享待扩展。

**目标用户：**独立开发者、内容创作者、设计师与活动策划者。

**用户问题：**想制作统一风格的小场景，但逐个建模和调整渲染需要较多技术投入。

选择街道或村庄模板，放置房屋、树木与道路，调整风格和地点内容，保存作品并导出一个网页。

**用户流程：**打开初始小镇 → 添加与移动组件 → 调整配色与预览 → 本机保存或 JSON 备份。

**现有基础：**三渲二渲染、共用场景组件、可复现场景配置、性能采样与导出、最小小镇编辑与存档。

**需要新增：**

- **组件与模板：**增加尺寸和配色参数、物件分组、多模板选择；协议变化需版本迁移。
- **布局约束：**增加重叠提示、自动避让、道路衔接和地形适配；当前拖动允许重叠。
- **内容与分享：**绑定地点内容与业务动作；按需求实现网页作品导出、账号和云端共享。

**最小方案：**已交付：房屋、树木和道路三类组件，增删、拖动、坐标移动、旋转、撤销重做、保存与重新加载，保留三渲二效果；JSON 可导出并重新导入。

**完成条件：**

- 用户无需改代码即可搭出一个可识别的小镇。
- 保存并重新加载后，布局和风格保持一致。
- 编辑中的性能达到选定目标设备的预算。

已实现演示：[最小小镇搭建器](../web/builder.html)；操作与验证见 [搭建器记录](builder.md)。

**适用条件：**当前限 40 × 40 米、60 个固定尺寸对象，允许重叠，不自动连接路网；没有云端同步或网页作品发布。真实触屏与目标设备性能仍待验证。

关联视觉：[林间村落](../web/lab.html#forest)。完整扩展方案见上述缺口，最小搭建器已有独立入口。

### 轻量探索与叙事游戏

游戏与陪伴；按需求推进；工程范围：高。已有场景与开门反馈，游戏机制待实现。

**目标用户：**喜欢轻松探索、短篇故事与收集的玩家。

**用户问题：**玩家需要一个有目标、有反馈、能记住进度的小世界。

在林间村落与一位居民对话，寻找三件物品，解锁茶屋并得到一份故事奖励；完成后保存进度。

**用户流程：**获得居民的委托 → 探索并收集物品 → 交付任务并解锁地点 → 保存进度和奖励。

**现有基础：**三渲二渲染、共用场景组件、可复现场景配置、地点与开店交互、性能采样与导出。

**需要新增：**

- **角色与路线：**角色移动、镜头跟随、碰撞、地面高度与路线可达性，分别验证键盘和触屏操作。
- **任务与叙事：**NPC 对话、物品状态、任务推进与奖励反馈。
- **进度保存：**定义存档格式、读取与重置；逐步扩展背包、经营或建造。

**最小方案：**做一个预计 5–10 分钟的任务，包含一位 NPC、三件物品、一个解锁地点与存档。时长是设计目标，需试玩确认。

**完成条件：**

- 玩家能理解目标并独立完成任务。
- 路线可达，任务不能因操作顺序而卡死。
- 退出再进入后任务进度正确恢复。

**适用条件：**增加建筑数量不能替代玩法设计；完整游戏还需内容制作、调优与持续试玩。

关联视觉：[林间村落](../web/lab.html#forest)。这是现有场景实验，不代表该产品已经实现。

### 品牌展厅与数字市集

内容与展示；按需求推进；工程范围：中。已有内容发现演示，业务接入待实现。

**目标用户：**品牌、创作者、市集与活动主办方。

**用户问题：**需要有主题感的展示入口，让访客理解产品或活动并完成下一步。

每家店对应一个产品系列或参展者，告示牌展示活动信息，点击进入产品说明、演示或报名入口。

**用户流程：**进入主题街区 → 发现店铺与内容 → 了解具体产品 → 访问购买或报名入口。

**现有基础：**三渲二渲染、共用场景组件、地点与开店交互、阅读与本机收藏。

**需要新增：**

- **可维护内容：**产品与活动数据、图片和链接管理，按需要连接内容后台。
- **业务流程：**接入真实产品页面或报名系统，清楚说明跳转目标与数据用途。
- **效果评估：**比较内容理解、目标入口点击与任务完成情况，并保留平面浏览入口。

**最小方案：**三个有真实内容的店铺，提供产品详情和一个明确业务入口；同时给出列表入口。

**完成条件：**

- 访客能找到目标产品并理解核心信息。
- 场景与列表都能完成相同的业务任务。
- 用真实使用记录评估价值，不能仅凭停留时间判断转化。

**适用条件：**三渲二能够形成主题风格；转化、销量和活动效果需要另行验证。

关联视觉：[樱花商业街](../web/lab.html#street)。这是现有场景实验，不代表该产品已经实现。

### 教育与文化探索

学习与文化；按需求推进；工程范围：中高。已有地点与阅读入口，学习流程待实现。

**目标用户：**教育内容作者、博物馆、文化机构与培训团队。

**用户问题：**需要把抽象知识或历史关系变成有上下文的探索过程。

在村落了解地方生活与建筑，在广场查看故事时间线，进入不同地点阅读讲解并完成观察任务。

**用户流程：**选择一个学习主题 → 探索地点与讲解 → 完成观察或问答 → 回顾掌握的知识。

**现有基础：**三渲二渲染、共用场景组件、地点与开店交互、阅读与本机收藏。

**需要新增：**

- **内容与教学脚本：**组织知识点、场景线索与讲解，核对史实和资源来源。
- **学习反馈：**增加问答、提示、回顾与学习进度。
- **可访问体验：**提供文字与键盘路径，验证目标设备、字号和教学使用方式。

**最小方案：**一个主题、三个知识地点和一个回顾任务，先验证是否能帮助理解具体知识。

**完成条件：**

- 学习者能解释指定知识点与地点之间的关系。
- 无需操控三维镜头也可获得全部知识内容。
- 讲解、题目与反馈一致，内容来源可追溯。

**适用条件：**美术风格不等于史实复原；学习效果需要通过具体任务验证。

关联视觉：[小广场](../web/lab.html#square)。这是现有场景实验，不代表该产品已经实现。

### 陪伴与专注庭院

游戏与陪伴；按需求推进；工程范围：中。已有氛围与组件，专注流程待实现。

**目标用户：**想记录专注和日常小目标的个人用户。

**用户问题：**希望用温和的视觉反馈记录持续行动与积累。

完成一次计时专注后种下一棵树，完成小目标后获得装饰，庭院逐渐形成个人记录。

**用户流程：**设定本次小目标 → 开始专注计时 → 记录完成情况 → 让庭院逐步成长。

**现有基础：**三渲二渲染、共用场景组件、可复现场景配置、性能采样与导出。

**需要新增：**

- **计时与任务状态：**正确处理暂停、后台、刷新与计时完成，不依赖动画帧数计时。
- **成长记录：**保存任务和庭院状态，允许修改、导出和重置个人记录。
- **长期体验：**设计轻量反馈与低资源模式，按需加入授权明确的声音或天气。

**最小方案：**一个计时器、一种成长奖励与本地保存，验证用户是否愿意持续使用。

**完成条件：**

- 刷新与后台切换后计时状态准确。
- 完成记录和庭院变化可以恢复。
- 视觉反馈对专注体验有帮助，运行资源符合目标设备预算。

**适用条件：**陪伴与专注是体验目标；不作医疗或心理疗效承诺。

关联视觉：[林间村落](../web/lab.html#forest)。这是现有场景实验，不代表该产品已经实现。

### 多人社区与活动空间

社区与协作；后期探索；工程范围：很高。已有空间展示，多人系统待实现。

**目标用户：**小型社区、远程团队与线上活动主办方。

**用户问题：**希望通过位置和主题区域组织相遇、讨论与活动。

角色在广场见面，进入讨论区域，查看活动内容，并按权限加入小组交流。

**用户流程：**进入活动空间 → 找到人或主题区域 → 参与交流与活动 → 留下内容和下次入口。

**现有基础：**三渲二渲染、共用场景组件、可复现场景配置、地点与开店交互、性能采样与导出。

**需要新增：**

- **实时状态与身份：**服务端房间、角色状态同步、身份、权限、断线重连与人数预算。
- **交流能力：**先接文字或既有会议服务，再按需要研究音视频与距离交流。
- **社区运营：**活动组织、内容治理、隐私和访问管理。

**最小方案：**限定人数的房间，先同步角色位置并接入文字交流；先验证共同活动的需求。

**完成条件：**

- 多个用户看到一致的房间与角色状态。
- 权限、离开和断线重连行为正确。
- 目标人数下有可接受的同步与渲染表现。

**适用条件：**联网、身份与运营成本明显增加；当前单机场景没有这些能力。

关联视觉：[小广场](../web/lab.html#square)。这是现有场景实验，不代表该产品已经实现。

## 推进顺序

顺序依据现有实现和研究集用途判断；付费意愿、使用效果与商业模式需要另行验证。

### 先完成研究小镇的多项目流程

最贴近现有研究集：先实现多项目数据、搜索和直接链接，验证内容能持续接入。

### 继续验证小镇搭建器的创作体验

最小编辑与保存已完成。先让实际用户完成一个小镇，再按反馈扩展模板、布局约束和地点内容，测量目标设备性能。

### 按明确需求扩展玩法或服务

游戏先做一个完整任务；展厅先做一次内容到业务入口的流程；多人空间先验证小规模共同活动。

## 分层复用

渲染、场景、交互与业务内容分层复用。新用途先明确一个完整用户流程，再增加所需能力。

### 风格与渲染

当前：toon.js、post.js、outline.js 提供独立管线。

扩展：沿用固定 Three.js r180；新增模型逐项检查法线、材质、透明与配色，再验证风格。

### 组件与布局

当前：lab/components.js 和 lab/configs.js 分离组件与布局；builder/model.js、world.js 提供编辑配置和对象生成，沿用相同组件。

扩展：扩充组件参数、模板、避让和道路规则，保存协议演进时提供版本迁移。

### 地点与动作

当前：研究街通过地点 ID 触发业务动作；技术实验独立处理店门。

扩展：统一成可替换的动作适配层；阅读、任务、跳转与编辑按需要接入。此统一接口尚未实现。

### 内容与状态

当前：研究街使用真实笔记与本机收藏，说明页共用产品方向数据；搭建器独立保存名称、布局与风格，并校验 JSON 导入。

扩展：新增项目、教学或任务数据时保留稳定 ID；跨设备同步、账号与后台按业务增加。

### 测量与交付

当前：技术实验记录参数、帧间隔与资源计数，可导出实际样本。

扩展：选择目标设备做重复基准，验证用户任务与平面入口，分别记录新增资源授权。

## 新场景接入步骤

1. 选择一个产品方向，写清目标用户、问题与可完成的最小流程。
2. 选择场景布局和统一风格，确定可复用组件与新增组件。
3. 把地点 ID 关联到真实内容或动作，定义需要保存的业务状态。
4. 增加必要的移动、编辑或服务能力，并保留直接访问内容的入口。
5. 验证任务完成、状态恢复、风格一致性和目标设备性能，再扩大规模。

## AI 辅助扩展

AI 辅助可以在配置协议与校验稳定后生成受约束的配置草案，再预览和人工修改。当前没有 AI 生成或任意描述自动生成可玩世界的能力。

## 内容数据的维护与复用

本文件是产品研究内容协议 v1，包含理解、能力、方向、缺口、最小方案、完成条件和复用分层。修改后运行 content:sync 生成中文笔记；网页读取同一数据。它与 lab 的测量配置、builder 的 sakura-town v1 存档格式分开，不能直接导入搭建器。

数据源：[product-directions.json](product-directions.json)。在 `web/` 下运行：

```powershell
npm.cmd run content:sync
npm.cmd run content:check
npm.cmd run build
```

`content:check` 校验稳定 ID、能力引用、场景关联、必要描述与笔记同步状态；构建前自动运行。新增方向应保留已有 ID，为新方向分配新 ID。场景跳转仅使用已有的 `street`、`forest`、`square`。

维护协议与实现说明见 [复用说明](../web/README.md#产品方向内容的复用)。本笔记由 JSON 生成，请修改数据源后同步。
