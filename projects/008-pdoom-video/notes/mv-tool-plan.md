# 定制角色 MV 工具实施方案

可以在 PDoomVideo 的动画与渲染思路上实现“定制角色、上传音乐与歌词、选择画风、自动生成分镜和 MV”。可控的起步方案是让模型生成结构化分镜，再由角色、动作与场景模板执行。工具运行层建议适配作者的 ClaudeAnimationBase，PDoomVideo 用作效果与叙事参考。

方案最初用于界定首版范围。2026-10-11 已实现本地最小工具，角色、上传、画风、规则分镜、预览和 MP4 导出通过；模型适配器已实现但真实服务未配置。当前实现、接口及验收证据以 [本地工具记录](local-tool.md) 和 [Web README](../web/README.md) 为准；下文保留更完整的目标，未全部完成。

## 首版范围

| 功能 | 第一版交付范围 | 后续扩展 |
| --- | --- | --- |
| 定制角色 | 一种参数化二维角色模板，编辑名称、颜色、比例、表情和服装 | 图片角色、部件分层、骨骼绑定、多角色互动 |
| 音乐 | 本机上传 MP3/WAV，取 15～30 秒片段；探测时长并允许输入 BPM 和首拍偏移 | 自动节拍与段落检测、变速节拍轨道 |
| 歌词 | LRC/SRT 或纯文本；显示歌词时间来源，允许手动调整 | 中文唱词强制对齐、逐词时间与口型 |
| 画风 | 水彩绘本、墨线素描、平涂卡通三个固定适配器 | 更多经过实现和验收的风格包 |
| 自动分镜 | 模型根据歌词、情绪和可用模板输出 JSON；支持局部重编排 | 多轮故事规划与新场景资产生成 |
| 预览与编辑 | 分镜列表、时间轴、关键帧联系表、简化动画预览 | 波形编辑、动作曲线、连续高质量预览 |
| 导出 | 16:9、24 fps、720p/1080p MP4，异步作业和明确进度 | 9:16 构图、多规格批量导出和远端 worker |

角色定制首先是“已有可动模板的外观与参数编辑”。任意图片要稳定表演，还需要识别身体部件、分层、绑定和补画；这部分不能通过增加上传按钮解决。画风由线条、填充、纹理与运动规则共同定义，三个适配器必须各自实现，不能仅换配色后宣称支持三种画风。

## 用户流程

1. 创建工程并编辑主角，保存为角色配置。
2. 上传音乐，选择片段，导入歌词；显示时长、节拍与歌词时间来源。
3. 选择画风和情绪倾向，自动生成可编辑分镜。
4. 查看每镜头的歌词、动作、场景、相机和时长，修改或只重写某一镜头。
5. 生成关键帧与简化预览；可直接采用默认分镜，也可调整后导出。
6. 后台渲染和编码，完成后提供 MP4、分镜 JSON 与工程配置下载。

纯文本歌词没有准确唱词时间。首版只能生成估计时间草稿并清楚标注，允许校时；不能将等分或按字数分配宣称为自动声学对齐。LRC/SRT 的外部时间也应允许整体偏移和人工修正。

## 系统结构

```mermaid
flowchart LR
  U[角色 音乐 歌词 画风] --> A[导入与媒体探测]
  A --> T[歌词与节拍时间轨]
  T --> P[模型生成分镜 JSON]
  P --> V[结构 时间 模板校验]
  V --> E[分镜编辑与预览]
  E --> C[模板执行器]
  C --> R[Chrome 逐帧渲染]
  R --> F[ffmpeg 编码合成]
  F --> O[MP4 与工程文件]
```

| 模块 | 建议实现 | 关键输出 |
| --- | --- | --- |
| 编辑界面 | React + TypeScript；角色控件、音乐播放、歌词与分镜时间轴 | 工程草稿、编辑后的分镜 |
| 本机 API | Node.js + TypeScript；媒体文件、模型调用、作业 API | 素材 ID、分镜版本、作业状态 |
| 媒体探测 | ffprobe 检测真实编码、时长和采样率，ffmpeg 解码所选片段 | 媒体元数据与标准化音频 |
| 分镜规划 | 服务端可配置的语言模型；结构化输出和两次以内修复 | 符合数据契约的分镜 |
| 动画执行 | ClaudeAnimationBase 适配层、模板注册表、角色和画风配置 | `renderAt(t)` 与关键帧 |
| 渲染作业 | Puppeteer、独立工程工作目录、帧校验与缓存 | 帧序列、完成率与失败位置 |
| 编码与核验 | ffmpeg；检查退出码，ffprobe 与完整解码检查 | 可播放 MP4 和输出元数据 |
| 工程保存 | 首版使用文件 manifest 和作业日志，之后再引入数据库 | 可重开工程和可恢复作业 |

模型密钥只存在服务端。语言模型接收歌词、角色描述、画风规则、时间轨与可用模板，不必上传完整音乐文件；声学对齐若使用外部服务，需要另行说明音频传输位置。本机预览、AI 分镜和视频编码属于不同阶段，不把离线规则模式显示为 AI 成功。

## 自动分镜的实现方式

先提供六类已实现模板：角色登场、场景行走、道具互动、情绪反应、舞台舞蹈和结尾谢幕；每类规定可用动作、道具、相机与构图安全区。模型输出镜头的时间、叙事目的、模板、动作、情绪和转场，使用统一主角 ID，副歌可复用场景并逐次升级。

为了保持剧情，先形成一句话故事与开端、变化、结尾，再生成镜头。模型应结合整段歌词和音乐片段结构安排内容，而不是把每句歌词随机配一个场景。节拍位置负责约束动作落点，歌词语义负责镜头内容。

输出按 [分镜契约](storyboard-contract.md) 校验：字段类型、镜头时长、完整覆盖、歌词和角色引用、模板能力、字幕安全区及性能预算。当前 `1.0.0` 实现了类型、时间、引用、选段校验和六个场景模板，模型错误最多修复一次；更完整的性能预算和失败草稿编辑仍待增强。原 [人工示例](../examples/storyboard.example.json) 是 `0.1.0` 设计草案，不能直接导入实际工具。

| 路径 | 优点 | 代价 | 本项目选择 |
| --- | --- | --- | --- |
| 分镜 JSON 调用模板 | 容易编辑、校验、复现和局部重试 | 创意范围受模板限制 | 首版主路径 |
| 模型直接生成任意 JavaScript | 可以新增动作和独特场景 | 编译、性能、调试与执行隔离成本高 | 后续创作实验；在独立环境中验证后入库 |
| 生成式视频逐镜头出片 | 可覆盖更多视觉风格 | 另需素材一致性、时间控制和视频服务 | 独立扩展，不属于现有代码能力 |

## 音乐与歌词分析

首版先依靠可调 BPM、首拍偏移与带时间歌词闭合链路。自动节拍候选是 [librosa 0.11.0 beat_track](https://librosa.org/doc/0.11.0/generated/librosa.beat.beat_track.html)，它从起音强度、节奏估计和峰值选择得到节拍位置；算法能输出空节拍轨，因此要保留手动设置和倍速、半速修正。

后续歌词对齐可评估 [WhisperX](https://github.com/m-bain/whisperX) 的语音与强制对齐流程。其官方定位是语音识别和时间对齐，不能由此保证中文歌曲、拖长唱音、伴奏和重复副歌的准确率。本项目未安装或测试这两个候选组件。

声学实验应以已有正确歌词为约束，可尝试人声分离后对齐，测量每句起止误差并允许修改。对齐失败的句子进入显式的“待校时”状态。人工校时后才形成可信时间轨；估计时间仍可用于草稿预览，但显示其来源。

## 预览 渲染与恢复

原仓库 `--w` 只改变联系表缩略尺寸，仍绘制完整 1920×1080。快速预览需要真正降低内部画布分辨率、使用简化画风或缓存关键帧。正式水彩输出作为异步作业；本机九帧抽样不足以确定 worker 数，需以 1、2、4 worker 和不同质量级别实测。

缓存键包含素材内容哈希、选段、歌词轨、分镜、角色、画风、种子、分辨率、fps、字体和渲染器版本。修改工程后不复用旧版本帧；镜头重编排只重建受影响范围与转场邻接帧。编码前检查预期帧数、连续序号和图片可解码性。

状态建议为 `queued → rendering → encoding → complete`，并提供 `failed` 和 `cancelled`。记录已验证帧、配置快照和失败原因；重启后可恢复相同版本任务。一个任务失败要关闭它的 Chrome 和 ffmpeg，不影响其他工程。

以 30 秒、24 fps 为例，共 720 帧。若实际有效平均耗时为 1 秒/帧，画面生成约 12 分钟；这是计算示例，不是实测承诺，还没计入启动、编码和检查。模型费、声学分析费、GPU 时间和素材存储分别统计，发布前再按选定模型及机器实测定价。

## 接口草案

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| `POST /api/assets` | 本地音乐或歌词文件 | 素材 ID、类型、大小与探测结果 |
| `POST /api/projects` | 角色、画风、音乐选段、歌词轨 | 工程 ID 和版本 |
| `POST /api/storyboards` | 工程版本、创作要求 | 生成任务 ID，随后取得合法分镜或失败原因 |
| `PATCH /api/projects/:id/storyboard` | 编辑后的分镜和当前版本 | 新版本；旧版本写入冲突应拒绝 |
| `POST /api/previews` | 工程版本、镜头范围 | 联系表或预览任务 |
| `POST /api/renders` | 工程版本和输出规格 | 渲染任务 ID |
| `GET /api/jobs/:id` | 作业 ID | 阶段、已完成帧数、结果或错误 |
| `POST /api/jobs/:id/cancel` | 作业 ID | 取消状态 |

上表是目标接口草案。最小工具采用简化接口：实际 `/api/assets`、`/api/lyrics`、`/api/storyboards`、`/api/renders` 和 `/api/jobs` 已可调用；工程以浏览器草稿与任务快照保存，尚未实现独立的项目版本冲突接口。文件和模板引用由内部 ID 解析，模型输出不包含脚本执行、任意本机路径或远程资源地址。

## 实施顺序与验收

| 阶段 | 实现内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| A 渲染闭环 | 固定通用基础库、保留 MIT、手工分镜驱动一个自有角色 | 15 秒带音频 MP4 完整播放，固定种子重渲染和失败资源清理通过 |
| B 工程编辑 | 角色参数、音乐选段、歌词轨、画风选择和文件保存 | 工程重开一致；不同角色参数与三种画风有真实视觉差异 |
| C 自动分镜 | 服务端模型、约束提示、JSON 校验、修复和局部重写 | 真实模型在至少五组歌曲与歌词上产生可执行分镜；失败不伪报成功 |
| D 稳定导出 | 异步任务、缓存、进度、取消和恢复 | 缺帧不编码；改配置不误用缓存；取消不留下进程；断点恢复保持版本 |
| E 自动声学分析 | 节拍估计、中文歌词对齐与修正界面 | 建立样本集和人工标注误差，记录失败率及适用范围 |
| F 角色与格式扩展 | 图片角色、多主角、竖屏、更多风格 | 逐项建立绑定、角色一致性与构图验收 |

A 到 D 是首版主线，E 和 F 为后续增强。开发周期取决于角色和模板的数量、声学要求、画风效果及机器性能；现阶段不报未经验证的工期。

核心验收除了构建检查，还应覆盖真实文件上传、歌词时间解析、不同素材下的分镜、中文字幕、超时与无效 JSON、视频流和音频流、时长、完整解码及人工观察。计划目标是片段音画总时长误差不超过一个视频帧，句级字幕起点相对标注误差不超过 300 ms；这些为目标，尚未达到或测量。
