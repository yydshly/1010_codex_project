# PDoomVideo 与纸间 MV · 提交与交付摘要

从一支预编排的角色 MV 提炼可复用方法，让自己的角色随音乐出演故事。已实现本地「纸间 MV」，跑通角色定制、音乐歌词输入、规则分镜、预览编辑和短片导出。

## 1. 源库能力与效果

- **作品定位：** PDoomVideo 为固定歌曲、Clawd 主角和九章剧情提供完整动画源码。角色、表情、动作、道具、镜头和歌词共同承担叙事。

- **视觉效果：** p5.js 与 p5.brush 组合水彩、墨线、排线、纸纹和线条变化，形成绘本风格。歌曲和时间表已编排，更换歌曲需要重新设计分镜。

## 2. 本地工具能力

- **输入与定制：** 编辑角色名称、颜色、比例、眼睛、头饰和情绪；上传 MP3/WAV 与 TXT/LRC/SRT，选择 15～30 秒片段和三种预设画风。

- **创作与交付：** 依据歌词关键词与手动 BPM 生成规则草案，编辑场景、动作、情绪、镜头、转场和时间，随音乐预览，保存工程并导出 MP4。任务支持进度、取消、继续和缓存。

## 3. 模块与底层原理

- **模块链路：** 媒体输入与探测 → 歌词解析 → 工程协议与分镜校验 → 角色、动作、场景和画风执行 → 时间轴编辑 → 渲染作业、编码与验收。

- **画面如何生成：** 全局时间选择镜头，局部时间计算动作、情绪和相机；节拍拍位由 `(t − offset) × BPM ÷ 60` 给出。源库使用 p5.js / p5.brush，本地工具使用 Canvas 2D；Chrome 按帧取样，ffmpeg 合成 H.264 与 AAC。

- **AI 如何参与：** 作者用 Claude Code 辅助写分镜与代码，运行时执行已有 JavaScript。本地默认规则分镜；可选模型适配器返回受约束的镜头 JSON，已实现但未配置真实模型实测，也不接收音频文件。

## 4. 使用场景与价值

- **适用内容：** 歌曲片段、项目介绍、技术科普、品牌故事、动态绘本和活动祝福。当前最适合单主角、预设场景与 15～30 秒内容。

- **对我们的价值：** 角色、动作模板、歌词解析、分镜协议、编辑与导出流程可以复用，下一次创作有可运行的起点。分镜和画面可以检查、修改，真实样片与验证资料可以用于判断方案是否适合。

## 5. 意义

- **内容资产：** 同一个自有角色可以持续出现在不同歌曲和故事中，积累稳定的视觉身份。

- **工程方法：** 把创作意图保存为结构化分镜，再交给可复现的执行器，使一次作品能够继续编辑、组合和迁移，为以后接入模型与其他渲染后端保留基础。

## 6. 扩展路线

- **近期：** 验证真实模型分镜，增加音频节拍、强弱与歌曲段落候选分析，允许人工校正，并比较剧情连贯性和修改量。

- **中期：** 扩充角色性格、动作与道具，完善跨镜头承接、歌词校时、局部重写、高质量画风、竖屏和按镜头缓存。

- **远期：** 图片角色绑定、多角色互动、演唱口型、云端作业与协作，以及独立生成式视频后端。分别验证角色一致性、音画对齐、可编辑性、耗时和成本。

## 7. 已验证结果与边界

- **本地成片：** 15 秒 / 720p / 360 帧和 30 秒 / 1080p / 720 帧均为 24 fps、H.264 / AAC，媒体规格与完整解码通过；30 秒流程另外验证取消续跑、缺帧重绘和缓存失效。使用原创合成伴奏，没有人声。

- **上游与模型：** 上游仅在本机核验九帧和 0.5 秒片段，未完整渲染原片。本地不会自动听懂音乐；真实模型、声学对齐、任意图片角色绑定和演唱口型尚未验证或实现。

- **在线与本地：** [公开网页](https://yydshly.github.io/1010_codex_project/008-pdoom-video/research.html)提供研究、原始图片、真实成片和资料阅读。音乐上传、角色创作、模型请求与编码使用本地服务；静态网页不承担创作后端。
