B / 自有保存

读取当前媒体，再交给浏览器

  1. 从图片、视频或音频元素取媒体来源。
  2. 视频 / 音频发出 Range 请求并核对范围。
  3. 分段写文件，或累积 Blob 后触发保存。

体验：自有视频路径显示进度；图片与语音没有同样的进度框。

源码 L150–480 ↗
交互示意 · 无网络请求

Range 到底在数什么？

假设文件只有 1,000 字节，每次示例响应返回 200 字节。切换分段，观察已读数量和下一偏移。实际脚本请求剩余范围，响应块大小由服务端决定。


      
协议依据：MDN · HTTP Range ↗。Range 使用从 0 开始的字节位置，结束位置包含在范围内；服务端也可能忽略范围并返回 200。这里的响应处理说明属于教学推导，不是对上游的修复。

      
分段写入文件
检测到 showSaveFilePicker 时，取得文件写入对象。减少累积整个文件的需求，但仍要正确等待每次写入与关闭，并处理取消和错误。
Blob 内存回退
把读到的 Blob 累积，再创建对象 URL 和下载链接。实现简洁，但大文件会增加内存需求；不能凭源码给出统一容量上限。
为什么页面能播放很关键？
脚本依赖网页已建立的账号与媒体取数环境，没有自建登录、MTProto 协议或解密流程。可访问范围仍由当前账号决定。

      
浏览器接口参考：MDN · showSaveFilePicker ↗。接口存在不代表下载一定成功，本研究尚未逐浏览器验证文件写入路径。

容易混淆的几个问题

        
能下载我没有访问权限的私有频道吗？＋
所查实现依赖当前账号能查看的网页媒体，没有增加未获访问权限频道的实现。上游关于受限保存内容的介绍，应理解为页面保存入口的增强；访问权限与保存入口是两个不同条件。

        
这是 Python 库、机器人，还是桌面应用？＋
研究版本是 JavaScript 浏览器用户脚本，靠脚本管理器运行在 Telegram 网页里，没有独立后台。这个中文研究网页是自有说明页面，不在浏览器中运行上游下载器；受控实验已执行原函数。

        
下载的是原画质吗？GIF 一定还是 GIF 吗？＋
保存的是当前网页端能取得的媒体。源码没有质量增强或转码；默认后缀不证明文件编码，GIF 类动画可能实际是视频。原图、最高画质及多分辨率选择都未实测。
多分辨率上游反馈 #130 ↗

        
分段读取就是断点续传吗？关闭进度框会取消吗？＋
Range 只是从指定字节位置读取。断点续传还要保存任务状态、验证来源与恢复写入；主线没有成熟实现。所查关闭按钮只移除进度界面，没有停止请求的机制。

        
能一键下载整频道，然后自动转写和总结吗？＋
所查主线没有成熟的整频道归档、持久化队列或 AI 处理。批量功能有独立提案，不能当作已合入能力；转写、OCR 和搜索均是本研究的扩展设想。

大文件和不同浏览器都能用吗？＋
保存路径随浏览器接口而变。Blob 回退可能增加内存需求，文件写入也要覆盖用户取消和错误。没有统一容量上限、完整浏览器测试或实体设备结果，当前不能承诺兼容所有情况。

        
没有按钮或下载失败，先检查什么？＋
这是待执行的排查顺序：确认脚本启用与匹配域名；记录 WebK / WebA、媒体是否加载；检查 DOM 入口、HTTP 状态与范围头；最后核对文件写入错误。完整性讨论中的现象是上游反馈，本研究没有全部复现。
