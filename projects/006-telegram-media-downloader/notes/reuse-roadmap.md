# 扩展路线与实施条件

以下是研究设想，未实现、未验证效果。目标是把可访问且获授权的媒体保存，扩展为可追溯的个人研究资料流程。

| 阶段 | 要做的事 | 验收条件 |
| --- | --- | --- |
| P0 可靠保存 | 等待写入和关闭，传递错误，区分 200/206，核对最终字节数，停止真实请求 | 小文件、大文件、模拟异常均不会误报成功；比对输入输出哈希 |
| P1 用户选择与队列 | 批量选择、限速、重复任务拦截、任务状态、失败重试 | 用户能确认所选对象，任务切换不会下载错误媒体；刷新后的恢复策略明确 |
| P2 来源整理 | 保存消息来源、时间、标题、文件哈希，按频道和日期分类 | 本地索引可定位来源，重复文件不会静默覆盖；敏感来源记录可由用户控制 |
| P3 知识检索 | 图片 OCR、语音转写、摘要、全文搜索 | 能查看原文与生成内容，明确模型错误、调用费用及外部传输范围 |
| P4 平台适配 | WebK/WebA 分离，统一媒体描述与下载引擎，变化监听 | 页面改版的失败能定位到适配层；每个平台独立维护验证样例 |

不建议在下载可靠性未确认前加入无人值守整频道抓取。主线的批量功能提案见 [Issue #159](https://github.com/Neet-Nestor/Telegram-Media-Downloader/issues/159)，本次没有验证提案作者的分支或原型。

对个人研究集，优先级最高的增量是“保存来源与检索”，而非采集数量。待取得真实使用频率和资料检索耗时之后，再决定是否值得开发生产工具。
