# 剧情规划与视频／口型接入

2026-10-11。新增能力建立在现有控制面之上，原始源码快照与成片继续保留。视频模型和口型模型尚未配置；本轮没有调用真实视频或口型服务。

## 现在能操作的流程

打开本机工作台，选择“映序 · 剧情与模型接入示例”，点击顶部“剧情与镜头”。

1. **分镜规划**：填写故事梗概、全片风格、连续性备注，以及每个镜头的叙事目的、地点、动作、景别、情绪、台词和生成提示词。镜头直接对应现有场景时间轴。
2. **角色设定**：最多12位角色，保存姓名、外观与服装描述、项目内参考图片和可选音色ID。每个镜头选择出场角色和一个配音角色。
3. **生成任务**：选择“动态视频”或“人物口型”，保存请求快照。模型未配置仍能准备任务、下载JSON。明确提交后才发送媒体到已配置的服务。
4. **结果审核**：模型生成的视频先入素材库；也可以把已有视频关联为“手工导入”。播放器审核后点击“应用到镜头”，继续用原编辑器调整画布、旁白与导出。

“模型连接”新增独立的视频与口型配置，默认 `disabled`。当前实现 `studio-generation/v1` 自定义适配协议，并非任意供应商地址都能直接填写。原厂API需要一个映射到本协议的适配器。

## 适配器协议 v1

假设配置地址为 `https://adapter.example/studio/v1`：

- 提交：`POST /studio/v1/tasks`。
- 轮询：`GET /studio/v1/tasks/{id}`。任务ID只允许字母、数字、下划线、连字符，最长80字符。
- 凭据：仅把这一角色配置的 `Authorization: Bearer ...` 发往同一适配器。拒绝重定向；不会把配音密钥传给视频模型。
- 单次HTTP请求最多90秒；提交只执行一次，后续约每2秒查询一次，最多300次。无自动计费重试。适配器应按 `requestId` 实现幂等。

提交体的主要字段如下，完整真实例子见 [下载请求示例](../assets/production/lipsync-request.json)。

```json
{
  "protocol": "studio-generation/v1",
  "requestId": "工作台生成的UUID",
  "kind": "video 或 lipsync",
  "model": "配置的模型ID",
  "sceneId": "scene-4",
  "prompt": "完整生成描述",
  "negativePrompt": "需要避免的内容",
  "duration": 10.3,
  "aspectRatio": "16:9",
  "story": {"logline": "故事梗概", "style": "视觉风格", "notes": "连续性备注"},
  "shot": {"characterIds": ["presenter"], "speakerId": "presenter", "action": "自然讲述", "camera": "正面中景", "mood": "友好"},
  "characters": [{"id": "presenter", "name": "讲解员", "reference": "portrait.png", "voice": "voice-id", "description": "人物设定"}],
  "referenceImage": "portrait.png",
  "referenceVideo": null,
  "audio": "scene-4-voice.mp3",
  "narration": "当前镜头台词",
  "timing": {"audioIn": 0, "delay": 0.2, "volume": 1, "videoIn": 0},
  "media": [
    {"id": "portrait.png", "mimeType": "image/png", "dataBase64": "..."},
    {"id": "scene-4-voice.mp3", "mimeType": "audio/wav", "timelineAligned": true, "dataBase64": "..."}
  ]
}
```

参考文件字段是**项目内文件标识**，不能当成远程URL。实际提交时附带 `media` 字节；浏览器下载的请求JSON只有说明与引用，不包含素材字节或密钥。适配器需要将其上传到目标服务或转成本地模型输入。

口型音频已按旁白入点、延迟、音量和镜头时长预处理为24kHz单声道WAV。当 `timelineAligned:true` 时，应从0秒使用该音频，**不得再次套用延迟或入点**。文件ID仍指向原旁白，仅作为关联标识。参考视频尚保留完整原片，适配器按 `timing.videoIn` 和 `duration` 取片段。返回口型视频不能短于请求时长（容差0.15秒）。

响应支持同步返回完成，也支持异步轮询：

```json
{"id":"provider-task-123","status":"queued"}
```

```json
{"id":"provider-task-123","status":"running"}
```

```json
{"status":"succeeded","output":{"video_base64":"完整MP4文件的base64"}}
```

失败返回 `{"status":"failed"}`。不在浏览器展示上游原始错误体，避免泄露服务细节或密钥。界面保留通用错误与任务状态。工作台会用FFprobe确认结果含视频轨道，并生成真实预览图。

当前参考图片／视频总和限制40MB；响应限制70MB，解码后MP4最大50MB。暂不支持远程结果URL、Webhook、上传预签名地址或服务端任务取消。原厂的URL结果需要由适配器下载并转为MP4 base64。

## 状态、保存与兼容

- 项目中保存 `story`、`characters`、各场景 `shot` 和 `generationTasks`，仍使用revision避免覆盖新版本。
- 请求为不可变快照。相关角色、风格、镜头、台词或音频参数变化后，旧任务显示过期并拒绝提交／应用；用户须准备新任务。
- 模型任务状态包括：准备、提交、排队、生成、待审核、失败、中断。手工结果另外标识“手工导入”。只有点击应用后才替换镜头画面。
- 任务提交时锁定该项目编辑。服务重启后把未完成任务标为中断；已收到的远端ID会保存，但不会自动恢复或重新计费提交。可从外部服务取得结果后手工导入。
- 每项目最多100条任务；项目副本保留角色与分镜、清空任务历史。
- 切换配音角色或修改角色音色，会使对应旁白需要重新生成。未指定角色音色时用默认配音配置；当前每镜头仍是一位说话者、一条旁白，未增加多人混音。
- 角色参考图只是模型输入，本平台还不提供身份一致性算法、动作生成算法或口型推理算法。当前导出仍会静音导入视频的原声，保留现有旁白；动态模型返回的环境音不会混入成片。
- 模型配置及密钥仍仅保留在服务进程内存；MiniMax继续读取已有环境文件。剧情与任务数据保存到本机项目目录，原经典界面仍可使用。

- 浏览器准备口型任务，下载请求JSON；未配置模型时按钮禁用，直接API提交也返回400“模型待配置”。
