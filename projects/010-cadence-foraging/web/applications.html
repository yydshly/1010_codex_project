01 / 能力不是一个用途

先把“学习”和“用它解决什么”分开

预测 / 判断

给输入，估计答案

历史位置 → 未来位移
工况特征 → 下一段读数
数值特征 → 类别或数值

反馈：真实答案
动作 / 奖励

选动作，看结果

局势 → 去哪家店
状态 → 宠物做什么
表现 → 选哪个难度档

反馈：实际结果的奖励
记忆 / 回查

留下关联，线索再读

02 / 12 组核心算法与机制

有的负责算回答，有的负责学，有的负责记住

这些是机制的分组，不是 12 个互斥产品。一个 NPC 可以同时用神经图、EP 风格参与量、Actor–Critic、TD、资格迹和联想记忆；一个预测器也可以同时用时序状态与 EP。

模型 / 推理参数学习反馈信号状态 / 记忆规划
库里还有哪些辅助与高级方向？

固定版本还导出唤醒调节 Arousal、状态与参数保存恢复、TemporalMemory 约束、Steered / Life / Governor 组合、观察者与多 Patch 端口组合等。它们影响何时计算、如何组合或如何续跑，不应都当成一种新学习算法。更深组合和实验分区有各自契约；本页没有逐一运行验证这些接口。

学习率、β、衰减、归一化、阻尼和迭代预算也是配置 / 数值策略。它们影响实际训练与成本，不自动增加语义理解、预测信息或业务价值。

04 / 从能力到业务

同一业务可以采用几条不同路线

捕鱼：预测器 + 几何控制

位置历史 → TemporalPatchNet 预测 → 游戏的弹道 / 碰撞算法决定射击 → 实际位置评分。当前命中不是用奖励学射击策略；如果再接 Brain 选射击时机，那是另一项需要独立验证的实验。

宠物：状态规则 + 学习选择

应用先提供需求状态与允许行为，再由 Brain 选择并接真实反馈；Trace 保留近期活动，联想矩阵记录数值关系。动作差异是否让体验更好，要用目标指标与用户评价另测。

模拟机器人：模型学习 + 目标规划

先用执行后的真实状态训练后果模型，再用 plan 优化控制输入。训练改模型参数，规划改候选动作；两者不能混成“规划时把想要的结果学成事实”。

异常线索：预测模型 + 应用判断

模型预测正常读数 → 新测量到达 → 应用算偏差并校准阈值 → 人工 / 独立标签确认。库提供预测或内部状态，业务负责异常含义与提示条件。

如果接入 LLM：它可负责文字理解、任务拆解和工具参数；Cadence 可承担一个数值预测或有限动作模块。模块间数据、奖励、执行和来源仍由应用管理。当前站点没有实现这项集成。

05 / 选择依据

先为问题选方法，再决定是否加 Cadence

问题条件先比较什么Cadence 值得探索的点
结果可以直接由规则算出脚本、几何、规则控制规则无法覆盖的持续适应；仍要证明增量收益
状态与动作很少，奖励清晰规则、表格 Q-learning可检查的局部学习与记忆研究；现有 NPC 未胜出
动作一次执行，结果即时独立效用打分、上下文 bandit有限选项适应的候选；无需强行增加长期价值模型
运动短时近似平滑匀速 / 匀加速度 / 转弯模型重复的非线性响应或模式联系
测量噪声与隐藏状态突出Kalman / EKF / UKF、合适的状态估计受控证据修复与动作条件模型对照
模式切换或非高斯估计IMM、多模型、粒子滤波等外部路线学习模式间联系；先定义生成模型与评估
数值序列中有重复结构简单回归、GRU / LSTM、同预算序列模型时序 EP、状态与局部机制的可检查实验
需要精确查过去事实数据库、日志、缓存近似关联 / 补全的研究，不替代事实来源
未来存在多个合理分支多候选 / 分布输出，并检验校准扩展输出设计；当前捕鱼只有点轨迹

规则、Q-learning 和匀速 / 匀加速度是本项目的对照实现；其他路线只在指南中讨论，没有全部接入。Q-learning 解释外部方法与来源 · 上下文 bandit：情境、动作、已选动作反馈

决定采用的依据应是：留出任务误差 / 回报、变化后恢复速度、旧知识保留、总耗时与内存。只有能学习或只有内部残差小，不能证明业务上值得用。

07 / 从设计到实现

先定义一个可验收的闭环

  1. 定义任务与最小输出

    只选一个：预测一个数、选一个动作、读一个关联或规划一个控制序列。列出成功指标与能接受的延迟。

  2. 确定可观测数据

    写下每个字段的含义、单位、时间戳、尺度与缺测方式。只提供当时可知信息；一组全零不自动代表“未知”。

  3. 确定反馈与来源

    监督给真实答案，奖励给执行结果。行动、回合、结果 ID 对齐；晚到结果只结算一次。想象与教学状态不进入事实记录。

  4. 建立简单对照

    同一输入、同一反馈、同一允许动作；匹配数据划分与计算预算。先确认最近值、规则或物理模型是否已经足够。

  5. 选择与配置模块

    监督序列选 TemporalPatchNet 候选；有限动作选 Brain 候选；近似记录与证据修复有独立模块契约。不要把所有状态都称为“记忆”。

  6. 检查数值与更新结果

    检查形状、有限值、求解资格、updated / 接受结果。一次失败计算不是一次已接受学习；检查的是模块实际返回契约。

  7. 留出验证与状态管理

    按独立对象、轨迹、会话或设备划分，记录旧任务保留与新环境恢复。生产续跑需保存参数、活动、记录、优化器和随机状态等完整组成；本项目未实现会话恢复导入。

import numpy as np
from cadence import Brain
brain = Brain.compose(4, 2, modules=(16,), seed=7, arousal=True)
observation = np.zeros((1, 4))
action = brain.live(observation)
# 应用执行 action，收集 next_observation 和 reward
next_action = brain.live(next_observation, reward=[reward])
# reward 属于上一真实动作；回合与延迟控制看完整实现。

规划与记忆怎么接？

规划要先验证后果模型，再向 TemporalPatchNet.plan 提供 inputs、goal、controls 与 bounds。controls 声明哪些输入端口可改；执行与再次测量由应用完成。Records、RecordPatchNet 和 BeliefPatch 的字段 / 端口、写入和训练各有自己的接口，不能把 Brain 的几行调用直接套过去。

08 / 后续探索

从最近可验证的改进开始

顺序探索方向需要看到的证据
1 · 现有场景加条件更长时长、更多线索、未见组合、相同模型条件切换新任务成功率 / 误差、恢复速度与旧条件保留
2 · 信息与模型消融加操作输入；物理基线 + 学习偏差；关闭记忆 / 轨迹相同预算下哪个信息或机制实际贡献收益
3 · 多分支与范围多候选未来、任务权重与不确定性输出覆盖、校准、漏报 / 误报；不能只画更多曲线
4 · 小业务离线原型独立无人机日志、设备趋势或模拟宠物按独立会话留出，强简单基线，完整成本
5 · 后果与规划从一维模拟控制到更复杂受控环境模型留出误差 + 实际执行到达目标，分别评分
6 · 记忆与长期运行冲突事件、旧知识保留、完整存档与续跑获取 / 干扰 / 恢复测试，以及重启后的状态一致性

对当前项目，直接价值是做可检查的学习实验：哪一步改变了回答、奖励到底影响了什么、强规则能否更便宜地做到同样效果。是否值得进入具体业务，需要这些实验的结果；目前未证明 Cadence 带来通用性能、低功耗或商业收益。
