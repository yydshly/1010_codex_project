# 街区线索与多步奖励：Cadence 何时值得用？

研究日期：2026-10-11。真实 Python Cadence `0.80.0`，上游固定为 [`19bee92756d1842176ad30b1cd01edbfbfa3f14c`](https://github.com/muellerberndt/cadence/tree/19bee92756d1842176ad30b1cd01edbfbfa3f14c)，GPL-3.0。渲染来源与授权见 [来源清单](../THIRD_PARTY.md)。

## 结论先行

增加线索、岔口和延迟奖励，并没有自动让 Cadence 更占优。本配置下，街口线索 + 终点奖励的总命中率为 **40.56%**；增加途中街区反馈后为 **74.31%**。两者都低于能记住路牌的规则和 Q-learning。持续显示线索也改善了 Cadence，但不能据此证明工作轨迹有效。

对当前研究集的价值是：已经可以直接比较奖励设计、短期状态、适应与旧技能保留，避免只看一个成功种子就选算法。若要做这个规模的可用 NPC，优先规则记路；想要可学习的有限状态行为，可先用 Q-learning。Cadence 更适合下一步机制研究，尚未测出本任务上的生产收益。

## 1. 新增场景与观看方法

本机服务启动后打开 `http://127.0.0.1:8190/route.html`，原即时奖励场景仍在 `/`。页面默认种子 7、街口短暂线索、终点奖励。

1. 选择 1× 并使用「前进一步」：看见路牌 → 选街区 → 选巷口 → 等待 → 抵达结算。每趟有四个环境时刻，两次动作决定。
2. 选择 32×「开始观察」跑完 360 趟。第 121 趟只迁移樱花路线，第 241 趟返回。观察每类线索自己的近期成绩，不只看总曲线。
3. 把奖励条件改为「街区反馈 + 终点奖励」，自动新建同种子实验，比较学习过程。线索也可切换为一路可见。
4. 「搬到西街南巷」保留当前学习状态；在途中操作会排队到下一趟生效，当前趟仍按旧地图评分。手动迁移关闭自动安排，最多 600 趟。
5. 导出 JSON 可回查每个环境时刻的公开观察、执行动作、等待、实际反馈和终点路线。加速动画只呈现每批最后状态，记录不删步。

场景光圈和顶部画面路牌供观众理解；控制器真正收到的是页面下方的 8 个观察值。抵达后画面保留刚结束的一趟，控制框与观察值已指向下一趟，因而两处路牌可能不同。

## 2. 协议：明确时间与奖励归属

路牌有樱花纹、灯笼纹。每趟先在广场选西街／东街，然后在该街的岔口选北巷／南巷。四条路线编码为 `街区位 * 2 + 巷口位`：0 西北、1 西南、2 东北、3 东南。对应店铺依次为花见团子、铃木饭团、青叶茶屋、春日面包。

| 环境时刻 | 已执行行为 | 实际反馈及 Cadence 调用 |
| --- | --- | --- |
| 1：广场到街区 | 第一次动作，东／西 | 稀疏模式实际奖励 0；途中反馈模式正确街区 +0.2、错误街区 −0.2；`live(巷口观察, reward, done=False)` 选择北／南 |
| 2：进入巷子 | 第二次动作，北／南 | 奖励尚未到，不调用奖励更新，不编造零反馈 |
| 3：途中 | 无新动作 | `wait(途中观察)`，保留第二次动作及其资格迹 |
| 4：抵达 | 无新动作 | `wait(抵达观察)` 后只结算一次：命中 +1、落空 −0.25；`live(下一趟广场观察, reward, done=True)` 发出下一动作 |

`done=True` 区分跨趟边界：清理临时轨迹与跨趟奖励资格，不重建脑、不清空学到的图参数和联想记录。第一动作的价值通过非终止转移学习；第二动作的结果要到终点才能更新。两个 wait 是实际 API 调用，不是装饰性暂停。

原始观察为 `[樱花纹, 灯笼纹, 广场, 岔口, 西街, 东街, 途中, 抵达]`。短暂模式在第一次选择后隐藏前两个值；持续模式一路保持。街区位置由各自第一动作决定，所以控制器后来可能处在不同街区，但原始字段、线索序列和反馈规则相同。食物映射、目标坐标、阶段编号和迁移通知从不传入控制器。

每种子运行三阶段，每阶段 120 趟，线索各 60 趟，随机交错且在不同条件中复用：

| 完整趟数 | 樱花纹目标 | 灯笼纹目标 | 目的 |
| --- | --- | --- | --- |
| 1–120 | 西街北巷 | 东街南巷 | 初学两条映射 |
| 121–240 | 西街南巷 | 东街南巷 | 只改变一类线索，另一类用于回查 |
| 241–360 | 西街北巷 | 东街南巷 | 恢复旧樱花映射，再查灯笼保留 |

这是有限的两个岔口决策，位置会参与状态学习。角色的平滑步行仍是表现层，没有连续转向、障碍避让或通用路径规划。

## 3. 三种控制器为什么这样比较

**真实 Cadence**：`Brain.compose(8,2)`，16 个联想区域单元、16 个工作轨迹单元，加输入与动作区域共 42 个单元。CPU 后端；工作轨迹幅度 0.3、衰减 0.2、巩固率 0.25、actor η 0.1、bias η 0.01、γ 0.9、唤醒启用。所有 live、wait、内部活动和记忆写入来自固定上游包。工作轨迹可以影响后续内部状态，但并不保证它能正确保留路牌。

**规则记路**：各自锁存实际看过的路牌；每类线索记一条候选路线，初始均为西北。终点成功就复用，失败按 0→1→2→3 试下一条。它没有预先知道正确映射，但候选初值恰好符合初始樱花任务，对该阶段有优势；樱花返回时则需巡查三次失败。途中反馈不改变这条明确的终点巡查规则；保持这项强枚举基线，让复杂学习系统必须解释额外成本。

**带路牌锁存的表格 Q-learning**：自行记住看过的线索，以 `线索 ×（广场／西街岔口／东街岔口）` 构成 6 个状态、12 个 Q 值。α=0.3、γ=0.9、ε=0.12。非终止更新为 `Q[s,a] += α * (r + γ * max Q[s',:] - Q[s,a])`，终点更新不自举到下一趟；等待不更新。初值全零，并列最大值随机选取。

这里没有把规则或 Q 故意改成无记忆算法。保留一位路牌是基线的人工状态设计，也是一项工程成本；若去掉锁存，短暂线索任务将不再是普通 Markov 表格 Q 的公平工作条件。三者信息来源相同，内部表示与先验结构不同，不能把它称为严格等容量比较。

## 4. 四种子完整结果

固定种子 7、41、42、43；4 种主条件 + 2 种关闭工作轨迹对照。共 **24 次运行、8640 趟、34560 个环境时刻**，每次同时运行三控制器。每种条件 1440 趟。成功定义为整条两步路线命中目标，统计包含初学与迁移损失。

| 线索 / 奖励 | Cadence | 规则记路 | Q-learning | Cadence 灯笼末 20 次 |
| --- | ---: | ---: | ---: | ---: |
| 街口短暂 / 终点 | 584/1440 = **40.56%** | 98.06% | 81.81% | 13.75% |
| 持续可见 / 终点 | 1036/1440 = **71.94%** | 98.06% | 81.81% | 100.00% |
| 街口短暂 / 途中 + 终点 | 1070/1440 = **74.31%** | 98.06% | 84.24% | 95.00% |
| 持续可见 / 途中 + 终点 | 1083/1440 = **75.21%** | 98.06% | 84.24% | 100.00% |
| 街口短暂 / 终点，轨迹幅度 0 | 731/1440 = **50.76%** | 98.06% | 81.81% | 38.75% |
| 街口短暂 / 途中 + 终点，轨迹幅度 0 | 1080/1440 = **75.00%** | 98.06% | 84.24% | 95.00% |

灯笼末 20 次是各种子返回阶段中最后 20 次灯笼遇见的命中率，再取均值；灯笼目标从未变动。这是保留指标，不等于全阶段成功率。规则各运行均命中 353/360，四种子 1412/1440；Q 稀疏 1178/1440，途中反馈 1213/1440。固定探索会产生长期失误，两次独立选择还会累积整趟风险。

所有 Cadence 种子结果（每次分母 360），避免只展示成功种子：

| 条件 | 种子 7 | 种子 41 | 种子 42 | 种子 43 |
| --- | ---: | ---: | ---: | ---: |
| 短暂 / 终点 | 141 | 171 | **48** | 224 |
| 持续 / 终点 | 234 | 298 | 291 | 213 |
| 短暂 / 途中 | 257 | 300 | 285 | 228 |
| 持续 / 途中 | 287 | 304 | 274 | 218 |
| 短暂 / 终点，轨迹 0 | 158 | 191 | 158 | 224 |
| 短暂 / 途中，轨迹 0 | 258 | 293 | 285 | 244 |

关闭轨迹后稀疏奖励反而更好，途中反馈基本相当。本实验**没有证明工作轨迹的净收益**。持续显示线索的收益说明可观测性会影响本配置的表现，不能代替对内在记忆的因果验证。轨迹与奖励资格迹是两种机制：本消融只改工作轨迹幅度，未关闭奖励学习的资格迹。

短暂线索、途中反馈条件的阶段平均值进一步展示适应与返回成本：

| 阶段 | Cadence 整阶段命中率 | 樱花末 20 次 | 灯笼末 20 次 |
| --- | ---: | ---: | ---: |
| 初学 | 60.83% | 50.00% | 100.00% |
| 单线索迁移 | 93.96% | 100.00% | 100.00% |
| 樱花返回 | 68.12% | 71.25% | 95.00% |

种子 7 的途中反馈运行中，Cadence 在中间迁移阶段 120 趟全部命中，返回阶段最后 40 趟为 97.5%，但完整实验仍只有 257/360，低于规则 353 和 Q 313。局部阶段优势不等于整个任务优势。

本机控制器调用均值约 Cadence **11–14 ms/趟**、规则 **0.04–0.06 ms/趟**、Q **0.26–0.31 ms/趟**，详细值在原始 JSON 和页面。包括每趟两次 transition 与两次 wait，排除初始化、HTTP、绘图和步行；未隔离系统负载，不是部署延迟或电能测量。实时页面在途中显示的是累计调用时间除已完成趟数，明确标注含进行中调用。

比较不同奖励条件请使用共同的**终点命中率**。途中模式每趟额外 ±0.2，不能把它与稀疏模式的累计奖励直接比较为算法改善。

## 5. 对你更有用的选择边界

| 你要实现的行为 | 当前更合理的选择 | 从本实验得到的依据 |
| --- | --- | --- |
| 少量线索、固定几条路线、失败后换店 | 规则记路 | 枚举简单、保留映射稳定、98.06% 总成功率且计算少 |
| 小型可编码状态、希望行为由奖励学习 | 带必要状态记忆的 Q-learning | 12 个值就能处理两步反馈与迁移；可解释、实现成本低 |
| 观察内在状态、学习图连接、研究记忆干扰 | Cadence 实验分支 | 已有真实 wait/live、联想记录、唤醒与局部学习的可观察闭环 |
| 多维连续观察、未知组合、动态身体或环境 | 先做更大的对照实验 | 可能使手写状态表与规则成本上升，但本次尚未验证 Cadence 能获得泛化或成本优势 |

新增复杂度时，把“更值得用”定义为至少一项可测收益：更少人工状态设计、对未见组合更可靠、旧技能下降更少，或在相同成功率下完整运行成本更低。先增加线索数量与未见组合的留出测试，再测连续线索及更长延迟；仍用强规则和适当的有记忆学习基线。若扩大状态后收益仍未出现，就不应因为框架机制有趣而升级生产 NPC。

## 6. 原理、来源与证据范围

Cadence 的输入驱动反馈神经图求解，工作轨迹影响后续求解，联想记录提供另一条快速记忆路径；奖励学习结合价值误差与资格迹更新行动关系。`wait` 维持待反馈动作的归属，`live` 消费实际反馈并产生新的决定。数值求解残差小，不代表路线学对；不同线索的外部命中率才是任务证据。

架构、图学习与高级引擎的详细边界仍见 [原研究笔记](research.md)。本场景使用默认 `Brain.compose`，没有环境预测模型、没有调用 TemporalPatchNet，也没有接入语言模型。来源为固定版本的 [持续行动 API](https://github.com/muellerberndt/cadence/blob/19bee92756d1842176ad30b1cd01edbfbfa3f14c/docs/world-model.md)、[记忆](https://github.com/muellerberndt/cadence/blob/19bee92756d1842176ad30b1cd01edbfbfa3f14c/docs/memory.md) 与 [学习](https://github.com/muellerberndt/cadence/blob/19bee92756d1842176ad30b1cd01edbfbfa3f14c/docs/learning.md)；具体接入协议以本地 `runtime/route_experiment.py` 为准。

限制：只有四个开发种子、固定小环境，未做等预算超参数搜索、统计显著性检验或独立确认。规则锁存、Q 状态表、Cadence 的配置都是工程设计，不能从此推导一般算法排名。特别是连续导航、更多任务迁移、生产成本优势与真实设备表现均未验证。

## 7. 复现与文件

在 `runtime/` 运行：

```powershell
uv run --locked python evaluate_routes.py --seeds 7 41 42 43 --phase-length 120 --out ../notes/route-evaluation-results.json
uv run --locked python -m pytest -q --tb=short
```

默认保存全部 8640 趟的两次行动、奖励、目标、线索与最终状态；加 `--include-steps` 还可保存所有环境时刻的观察。24 次实验的实际结束结果均保留，没有挑选最好种子。配置和代码 SHA256 在 [原始评估](route-evaluation-results.json)；Web 构建前从它生成摘要并校验三个运行源文件哈希，代码变动必须重新评估。

浏览器记录、逐步等待验证、响应式截图与测试凭据见 [新场景验证记录](route-verification.md)。本机演示已运行，尚未公开部署。
