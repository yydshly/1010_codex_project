# 本机验证：四店觅食与研究汇总网页

日期：2026-10-11。以下统计来自本项目实际运行，区别于上游气味实验与作者演示。

## 固定协议

Cadence commit `19bee92756d1842176ad30b1cd01edbfbfa3f14c`，包 `0.80.0`；CPU 后端。Python `3.12.13`、NumPy `2.5.3`、Windows 11。`experiment.py` SHA256：`f6d886d4c8c3dc664d8efdf283dd5c2716a73012ee18ad5b982da8764ebe1921`。

每种子 600 轮，A 团子 200 → C 饭团 200 → A 团子 200。三者使用相同固定观察 `[[1,0,0,0]]` 与各自的实际奖励，目标位置、阶段和迁移通知不传给控制器。命中 +1，落空 −0.25；各自环境副本不竞争食物。详细参数见 [研究笔记](research.md#本地实验定义)。

种子列表为 7、41、42、43，全部结果保留，没有删除失败阶段或择优种子。参数是本地任务配置，不是统一搜索后的最优配置；本次不是预注册研究或独立确认实验。

Q-learning 每阶段末 50 轮的平均命中率为 91.00%，规则为 100%。规则在两次迁移后各落空两轮，然后找到目标并一直复访；初始动作固定 A，初始阶段没有落空。Cadence 的学习与恢复需要更长过程，最终平静时减少探索；Q-learning 保持 ε=0.12，最高价值唯一时仍有 9% 的动作概率选到其他三店。

恢复指标定义：**某阶段内首次包含至少 18 次命中的 20 轮窗口，其结束位置**。位置从该阶段第 1 轮计数；最早只能是 20。它不是首次命中时间，也不保证后续永久稳定。规则的数值 20 不表示花了 20 轮才找回食物。

## 实际浏览器流程

生产构建页面由 `127.0.0.1:8190` 提供，同一服务提供真实 Python API。

- 种子 7 单步到第 1 轮：Cadence、Q-learning 去饭团店落空，规则去团子店命中；奖励和学习写入随实际反馈变化。
- 随后选 32×，自动运行到 600 轮：512 / 596 / 532 次命中，准确展示两个迁移标记与曲线。
- 最终构建再运行同一实验，第 416 轮暂停成功：Cadence 近期 50%、规则 93%、Q-learning 57%；点击继续后恢复步进。奖励总数保留两位小数，准确显示 −0.25 的反馈。
- 导出 [browser-seed-7-600.json](browser-seed-7-600.json)：与离线种子 7 的 600 行 `history` 全部一致；耗时属于不同运行，不要求相同。
- 完成后手动搬到 B 茶屋：轮数仍为 600，Cadence 奖励更新数 261、记忆写入数 263 与四个 Q 值保持；自动切换关闭。第 601 轮三者仍执行旧的 A 动作并落空，之后收到反馈。未提前告知它们新目标。
- 中文研究 Markdown 下载成功；随机种子 −1 显示边界错误；改为 41 重置后轮数、奖励、Q 值和写入计数归零。
- 390×844 浏览器视口下，种子 41 单步、搬到 D 面包店再单步均成功，页面 `scrollWidth` 不大于视口宽度，三个卡片及控制区正常堆叠。视口覆盖已恢复。
- 本次检查浏览器 error/warn 日志为空。没有模拟成功或跳过真实引擎调用。
