# Jevclip：从视频粗剪到可回查的研究证据

Jevclip 字幕驱动视频粗剪与研究证据的完整中文理解：以既有全景图引导，汇总精选与保守去水、带引用摘要、九组源码模块、Jev 结构化判断与代码策略及 FFmpeg 分工、场景与个人价值、缓存和人工校准、模型接入与多模态及资料库扩展；保留原创字幕研究工作台、原始笔记、来源许可与实测。真实 Jev 与摘要模型未调用，网页不导出剪辑成品。

更新日期：2026-10-12。固定版本：`3d4b13f6ecbb7f56cf212c5040b4b4e19d83967a`，0.1.1 Alpha，上游 MIT。真实 Jev 与摘要 API 未调用。

## 能力：从字幕筛选到两类视频和研究材料

Jevclip 接收视频及配套字幕，也能只处理字幕或文字稿。支持 SRT、WebVTT、JSON 等时间稿，保留源时间；没有时间的文字稿以段落定位。信息判断来自文字，不读取视频帧或音频，不内置语音转写。

源库将当前片段的内容分类、信息密度、夸大风险、独立可读性和关注点相关度组合成取舍依据。输出包括精选高亮、保守去水完整版、重新对齐的字幕、带源位置引用的摘要、判断报告和 JSON。

它适合语言内容的初筛与粗剪。高亮回答“有限时长内先看什么”，保守去水回答“哪些明确低价值内容可以移除”；没有进入精选的片段不自动等于应该删除。最终审片、精剪与事实核验仍需要人。

## 效果：理解产物，同时区分作者记录与本地实测

预期变化是把长讲解变成按原顺序排列的重点片段，或保留主要讲解的去水版，并为研究要点保留源时间和段落。它提供内容筛选依据，不负责镜头节奏、转场、配乐、调色或创意成片。

上游 README 展示了合成样本与一期真实中文技术讲解；三分钟精选只覆盖参考要点的一部分。这属于作者有限样本记录，不能当成跨领域、跨语言的通用准确率。

本项目固定版本的 101 项上游测试中 99 项通过，两个失败与 Windows 路径和 CRLF 测试夹具有关。真实 FFmpeg 的合成色块剪辑、片段顺序和字幕对齐已验证；模型传输测试采用模拟数据，没有独立验证真实 Jev。

原创演示素材约 3 分 20 秒、10 个片段，没有真人或配音。默认规则保留 8 段只是交互样例，不是 Jev 判断结果；网页的 15 项数据测试与浏览器回查证明流程可用，不能证明模型效果。

## 模块：九组职责组成可审计的处理链

输入与存储层由 subtitles.py 与 store.py 负责：解析字幕、按停顿和句子切段、绑定源位置、记录材料版本与判断。后续修改门槛时能够追溯原文，而不是只剩一个不可解释的摘要。

判断与策略层由 jev.py、rubric.py 与 labels.py 负责：远程请求、并发和重试、结构化问题、确定性取舍规则、人工标注与评估。模型给判断，业务代码决定如何使用判断。

执行与表达层由 reel.py、llm.py、summary.py 以及 pipeline.py / report.py 负责：预算选段和 FFmpeg、独立摘要模型、片段引用映射与覆盖检查、流程串联、报告和机器数据。网络失败与未判断必须保留为单独状态。

## 原理：Jev 判断、代码取舍、FFmpeg 与摘要模型各司其职

源库按约 20 秒组织字幕段，将视频标题和当前片段原文发送至 TypeSafe 的 /v1/systemone API，研究版本默认使用 jev-1.13.0，密钥为 TYPESAFE_API_KEY。字幕时间、视频帧和整个视频文件不参与这段文本判断请求。

Jev 是针对结构化文本决策的远程模型。Choice 返回类别概率，Score 判断 0–3 的信息密度，Noul 给出夸大、独立性和关注点相关性的 0–1 概率值。官方公开说明提及 RLCD 后训练与决策校准，完整底座、参数和训练实现未核实；库中没有 Jev 权重或训练代码。

价值分为 d / 3 × (1 − j) × f，其中 d 是信息密度，j 是寒暄、推广、空话概率之和，f 是最高关注点相关度；未设关注点时 f = 1。默认保留要求价值 ≥ 0.5、闲话 < 0.5、夸大 < 0.6，设置关注点时相关度还要 ≥ 0.5，门槛需要自己的标注校准。

高亮用背包算法在时长预算内选择，收益结合价值、独立性和时长，成本包括前后留白；默认预算 180 秒，片段保持原顺序。保守去水只在明确低价值条件成立时删除。部分依赖前文的片段会关联上一段，但没有完整语义连贯性保证。

每段多个窄问题合并请求，支持并发、重试与 SQLite 缓存。缓存依据完整请求中的模型、标题、原文和问题；只调整策略门槛或时长预算可以复用判断，改变关注点或问题则可能重新调用。摘要调用不因此自动免费。

## 摘要与回查：出处存在、覆盖完整、结论正确是三件事

另一个 OpenAI 兼容的生成式模型读取保留段并生成摘要、引用片段编号；代码把编号映射为源视频时间或文字稿段落。Jev 负责结构化判断，不负责写长摘要。

代码过滤未知编号，检查保留段是否被引用，对遗漏进行一次补写，并检查部分数字和英文名称。这能降低位置伪造或明显词项丢失，但不能保证因果关系、适用条件和每个命题都被原文支持。

上游 Markdown 输出时间标签；本项目网页提供可点击原文面板和播放器跳转。引用定位和人工纠正让研究可核查，但不能替代对上下文与结论本身的复核。

## 当前网页：可体验的字幕研究流程

「片刻」是原创静态浏览器应用，采用 HTML、CSS 与原生 ES Modules，无第三方运行时包。已实现文件选择和拖放导入 SRT、VTT、通用 JSON、whisper.cpp JSON、TXT / MD；字幕原文保留，无时间稿不估造视频时间。

关注点最多五个，采用可查看的关键词组或原文子串，多个关注点任一命中。配合全部 / 保留 / 舍弃时间线、原文搜索、逐段人工取舍和内容分布，帮助你检查规则的实际效果。

摘要采用保留片段的原句摘录，点击引用显示完整依据，并在关联视频时跳转源时间。可导入上游 segments.json 保留取舍、类别、分数与理由，未判断单独呈现；人工决定优先。

Markdown 导出包括取舍理由和完整时间线，字幕与取舍保存在该浏览器 localStorage，可主动清除。视频用本机 Blob URL，刷新后需重新选择。公开页面仍不调用 Jev、摘要模型或剪辑后端；导入与视频关联在浏览器处理。

## 使用场景：以讲解为主体的资料筛选

适合课程、技术教程、访谈、项目作者演讲和带旁白的功能演示：主要信息在字幕里，希望快速找到部署方法、实验数据、设计理由或局限，并保留完整出处。

对 GitHub 项目研究，可把教程和作者讲解与源码阅读、运行测试并列：先按关注点定位，再回看原文和演示，把有依据的内容写入中文 README、研究笔记和后续开发判断。

不适合主要依赖画面的无旁白操作、图表、未读出的 PPT、体育动作或视觉叙事。字幕错误、术语误识别、单段缺少前文，以及把转述宣传误判为推广，都可能导致重点误删。

## 对你的价值：积累可复用的研究证据与工程方法

直接价值是减少反复拖动进度条，让“这个库有什么用、某个结论来自哪里、演示证据在哪一段”更容易回答。中文研究材料有出处、版本和人工修正，下一次扩展项目时可以复用。

工程价值在于把狭窄模型问题、确定性策略、源位置绑定、缓存、失败状态、人工校准和可审计输出拆开。产品价值应落在你的具体研究流程，而不是只多一个摘要按钮。

如果很少研究长视频，直接收益有限；它补充代码分析与测试，不能替代源码审查、性能基准或事实核验。节省时间、准确率、成本与付费价值尚未测量，不承诺效率百分比。

## 扩展与验证：先证明筛选价值，再完成产品闭环

体验当前网页不需要真实 Jev。复现源库的语义筛选需要真实 Jev 或已有判断缓存；验证效果需要真实调用与人工标注；生成摘要还要另配生成式模型；剪视频由 FFmpeg 执行。可以设计可替换判断模型的接口，但替换后必须重新评估。

建议先标注约 50 个真实字幕段，对比关键词规则与 Jev，记录重点误删、漏选、无关保留、连贯性、摘要命题忠实度、延迟、调用量、成本和缓存收益。这只是试验起点，不能据此声称通用准确率。

近期路线是服务端 Jev / 摘要接入、模型版本与错误记录、领域门槛校准，再接本地或服务端 FFmpeg 导出与人工审片，形成从字幕到粗剪的完整体验。密钥留在服务端，明确字幕文本会发送外部服务。

后续可增加 ASR 与术语纠错、OCR / 关键帧和视觉证据位置、前后文复核、多视频检索、来源版本与要点证据关联。以上是规划，目前没有自动转写、画面理解、剪辑成品导出或多视频资料库。
