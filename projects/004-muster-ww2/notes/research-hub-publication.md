## 能力：可配置、可编辑的程序化资产系统

**资产组织。** Muster 将开发者编写的 TypeScript 模型统一为可检索资产：国家、类别、名称、历史资料与来源共同组成资料库。选择资产后能修改装备和外观、数量、横队或网格编队及间距，再观察实际改变的三维几何。新增模型要实现构建函数和资产定义，目录注册后才能进入配置器与展柜。

**配置与布局。** 编辑器支持整组和单体拖动、旋转、复制、删除、撤销重做，并把布局与相机保存在当前浏览器。稳定编队槽位与单体偏移允许调整个别模型后继续修改编队；六视图工具提供正反侧、顶底观察及 1.80 米参照人物。我们另加入营地布局 JSON 导入导出与校验。

**能力边界。** 这是实际可运行的代码资产集合，尚未接入文字生成 3D、扫描重建或大模型指挥。公开展示上限 300 是界面限制，默认展柜 280 个实例，不代表 280 种素材、全场 GPU 实例化或设备性能保证。米制比例来自资料与照片参考，精度不等于工程 CAD。

**研究版本。** 研究固定 Kenton-GMI/muster-ww2 的 7d2fa86ebc3b999eaf085831cdcd5dccefea63d4。资产协议、建模规范、来源与 briefs 随网页完整保留；本地新增道路、机库、帐篷、沙袋、油桶、补给箱与树木，使既有单位能在符合素材风格的机场营地中使用。

**媒体与授权。** 研究总图为 3840×4886 的本地排版 PNG，另有可编辑 SVG，直接嵌入十张原始运行截图。网页资料包自动收录全部中文笔记、截图、真实声音采样、布局和 JSON 报告，每项都有来源路径、字节数与 SHA-256。上游 MIT 和版权原文保留，字体与依赖按各自许可证记录。

## 模块：八个页面串联研究、工具与玩法

**阅读与引导。** index 首页提供引导图、完整摘要、六问、原理、价值、扩展路线、效果对照与五个真实内嵌应用；research 提供全部原文检索和阅读；evidence 提供所有图片、录音、布局与报告的阶段筛选、完整内容和下载。摘要之外始终保留完整证据入口。

**模型与场景。** archive 是 74 条资产的展柜与配置编辑器；harness 是多角度与比例审查；camp 连接营地编辑、镜头导览、天气光线、布局保存交换、时间轴、车辆与步兵动作、飞机起降、起落架及声音。首页一次加载一个场景，提供独立打开、全屏、暂停继续和关闭。

**协同玩法。** battle 提供三车切换、步兵交火、P-51 空袭、通信区争夺与规则电脑对战；airport 在这些单位之上加入两班步兵指挥、吉普侦察与补给、共享视野、有限弹药与空袭、两波防守和四阶段任务。两种玩法保留独立入口，暂停同时冻结战斗、动作、任务与声音。

## 原理：从资产定义到任务状态机

**数据与几何。** AssetDef 统一资料、占地、options、constrain、build 和 provenance；配置先经过兼容约束，再构造模型。机械几何使用圆角盒、旋转体、挤出、放样和重复部件；共享人体由 SDF 与 Surface Nets 构造，静态姿势和装备组合由程序控制。

**渲染与编辑。** 程序化噪声、三向投影和 PBR 材质表现表面，Three.js 配合光照、阴影、N8AO 与抗锯齿呈现微缩展柜。按材质合并和模板缓存减少重复构建，但烘焙会合并部分机械层级，构造时的实例网格也可能被展开。编辑状态、历史快照和 localStorage 负责布局恢复与撤销重做。

**运动与决策。** 动态层重新拆出车轮、履带、螺旋桨和起落架，以统一时间与路径驱动，双段腿 IK 组织支撑与摆腿，落脚触发 Web Audio 合成脚步声。战斗层使用 A* 导航、碰撞、视线、冷却、重力炸弹与范围伤害；任务层以状态机连接侦察、部署、补给、防守和恢复。电脑由规则驱动。

## 效果：素材如何变成可观察、可游玩的协作

**营地与动作。** 营地使用八类上游素材、26 个实例：两架 P-51D、两辆谢尔曼、一辆 M18、两辆 Willys、两门 M2A1、17 名步兵与班长。90 秒演示中五车沿路运输、12 名士兵巡逻、一架飞机滑行起飞并降落；车轮按路程滚动、履带逐节循环、士兵弯膝走路、起落架与舱门联动，声音有距离衰减。

**陆空演习。** 自由演习中玩家可切换谢尔曼、M18、吉普，各车保留位置、耐久和装填；四名友军步兵协同对抗三辆敌车、六名敌兵及空袭。三分钟内全歼敌方装甲与步兵，或无争夺占领通信区 20 秒获胜。吉普保持无武装定位，空袭有预警与实际落弹伤害。

**机场任务。** 机场任务限时六分钟：侦察两通道 → 小队部署并送首箱补给 → 两波防守 → 送第二箱并警戒机场八秒。补给恢复 12 米内存活单位耐久和弹药；主炮 18 发、步枪 30 发，驻守阵地减伤 40%；有限两次空袭且需要当前视野。吉普、步兵、装甲、飞机分别承担信息、守点、阻击与支援，已有轻松模式真实通关记录。

## 使用场景：展示、教学、配置与游戏原型

**内容展示。** 数字博物馆、军事模型收藏和教学可以采用资料卡、来源记录、米制比例与多角度观察，帮助比较装备轮廓和配置差异；正式教学或历史产品仍需要史料审校、课程内容和完整可访问性设计。

**创作工具。** 主题场景搭建器和产品配置器可以采用统一选项、配置兼容约束、编队模板、成组编辑与文件交换。资产接入协议可以泛化到建筑、角色或道具，但需要重新编写对应内容、尺寸规则与交互，不能只替换名称就得到另一类产品。

**互动研究。** 浏览器游戏原型可快速验证驾驶、交火、空袭、侦察、补给与任务分工；资产生产与评审工具可用六视图、参照人物和对照截图复查配置。当前证明的是可运行机制及一次任务闭环，商业转化、教学成效和长期留存尚未验证。

## 对我们的价值：资产扩充方法与可验证产品样本

**工程复用。** 得到一条可复现的“资源 → 场景 → 动作与声音 → 战斗 → 协同任务”链路。新想法可以接入真实单位、操作和证据，而不是只停留在画面；来源、版本、构建修复、规则测试、浏览器验收与原始材料集中保存，便于继续扩充。

**现有项目。** 对樱花街与小镇搭建器，优先复用资产接口、配置约束、稳定槽位与单体偏移、历史快照和多角度审查，继续保留自己的三渲二风格与几何预算。目前这些是有源码依据的接入建议，尚未完成跨项目组件提取或实际集成。

**研究资产。** 对玩法研发，机场任务验证了信息、资源、位置与单位职责的协作：侦察影响目标选择，补给影响持续作战，步兵控制阵地，装甲阻击，飞机提供有限支援。静态浏览器运行便于本机复现与分享；多人服务、物理引擎和模型 Agent 应按产品需求单独设计。

## 可扩展方向：先深化协作，再提取工具和服务

**玩法优先。** 近期建议增加伤员撤离、侦察情报时效、有限补给库存、路线威胁、任务分支、波次数据配置和关卡编辑，并为单位职责、资源耗尽、失败恢复与胜负条件补充实际验证。先让当前任务有更多策略选择，再增加单位数量。

**工具与性能。** 中期提取通用 AssetDef、配置约束、场景快照、编队与审查工具，形成可复用素材接入流程。性能方向包括 LOD、最终渲染的真正 GPU 实例化、后台生成与缓存预算；需要在真实手机和低性能设备上测量，并审查全部模型与选项组合。

**长期能力。** 长期可增加 GLB 导出、完整骨骼蒙皮、车辆与飞机物理、更丰富关卡、多人状态同步、回放及可解释的模型指挥接口。以上均是后续方向，当前未完成；工程 CAD、可打印性和生产精度需要独立建模与验证。

## 复现与发布

在本项目 web 目录执行 `npm ci`、`npm run test:battle`、`npm run test:airport`、`npm run build`。根目录执行 `npm run check`。以 `node scripts/verify-hub.mjs --prefix` 核对固定子路径、五个实际应用和资料；预生成总图直接随资料包发布，CI 不调用图片服务，也不需要浏览器生成总图。

根部署工作流构建 001、002、004 并组装到 `_site/`；main 更新触发 Pages。先核验 Actions 与实际 HTTPS 页面、模型、声音和资源，再登记在线演示；旧本地记录保留原日期及范围。
