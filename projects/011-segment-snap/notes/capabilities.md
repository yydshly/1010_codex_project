# Segment–Snap 的能力与第一阶段展示

研究日期：2026-10-11。源码固定为 `67ccf8765a9c409ad400ae4d6ed151f9449c8ed9`；依据上游 README、METHOD、DATA、RESULTS_VAL、论文 v2 与核心源码。作者结果不等于本机验证，本阶段未运行 GPU 推理。

## 输入与输出

输入是同一坐标系、米制单位和点序的 XYZ、RGB、法线；部件和把手使用两个对齐视图。任意图片、视频或模型文件不能直接视为符合输入合同。

部件输出包含 `pred_masks`、`pred_classes`、`pred_scores`，以及源码拼写为 `pred_axises` 的轴向和 `pred_origins`。掩码形状为点数 × 实例数，轴与原点为实例数 × 3。把手输出掩码、类别与分数；`is_child` 标记合并时增加的候选。

旋转 / 平移是运动语义，不是柜子、冰箱等一般物体分类。把手类别指其操作部件的运动类型。完整轨迹、运动范围、抓取、力学与操作策略仍需下一层能力。

## 三个预测器

| 模块 | 表示与职责 |
| --- | --- |
| 独立部件 | Volt-B 与 200-query SPFormer，在超点上预测大部件，提供最终部件 |
| 密集把手 | 逐点预测背景、旋转把手、平移把手，再聚类；位置参与铰链选择 |
| 联合部件与把手 | 自身的部件 query 特征结合细体素特征提出 child 把手，补充候选 |

三者分别训练，架构同族但权重不同。联合模型不是读取独立部件模型的已保存掩码；child head 使用自身 parent query 特征，在同一次前向中预测。查询与体素特征分别投影后形成掩码；训练使用 BCE、Dice 和非对称 Tversky 项，抑制小把手过度覆盖。

[联合预测源码](https://github.com/HyoKong/Segment-Snap/blob/67ccf8765a9c409ad400ae4d6ed151f9449c8ed9/arti3d/models/joint_spformer.py)

## 几何与语义连接

部件取半径 0.05 m 的最大连通区域作为拟合支撑，不修改输出掩码。PCA 找薄方向，投影凸包上的最小面积矩形给出平面内方向，不能描述成仅靠 PCA 完成全部包围盒。

旋转轴默认固定为世界 Z，平移轴采用表面法线。旋转部件从包围盒生成四条候选线，选择离附近把手最远的一条；关联阈值是把手中心到部件支撑点的距离小于 0.5 m。无附近把手时用支撑中心回退。原点是支撑中心到所选铰链线的垂足，不要求为轴端点。

[包围盒实现](https://github.com/HyoKong/Segment-Snap/blob/67ccf8765a9c409ad400ae4d6ed151f9449c8ed9/arti3d/geom/obb.py)、[运动解码](https://github.com/HyoKong/Segment-Snap/blob/67ccf8765a9c409ad400ae4d6ed151f9449c8ed9/arti3d/geom/snap.py)。这部分免训练，感知模型仍需学习。

密集把手以 0.025 m 半径聚类，删除少于三点的实例。联合 child 掩码阈值为 0.30，分数按 parent 分数的 0.05 倍追加；保留原密集检测。仅修正新增 child 的类别：优先用包含至少 90% child 点且分数合格的独立部件，否则使用密集把手类别回退。掩码与分数不因修正改变。

两个方向各执行一次，没有最终把手到运动解码的循环。几何选择、额外候选和类别修正是不同贡献，不能把不同 AP 增益相加。

## 效果与边界

完整来源见 [evidence.json](../web/data/evidence.json)。固定掩码、轴、类别和分数，仅换原点规则，运动综合 AP 为 `13.74 → 40.98`；增加候选，把手 AP 为 `24.63 → 29.65`；完整类别修正后为 `30.99`。旋转原点改善不等于部件分割改善，平移原点不参与该指标。

195 个训练场景用于优化，42 个公开验证场景参与了权重和参数选择。近似平面、竖直铰链是主要假设；非竖直铰链、特殊平移方向、缺失把手和破碎扫描可能失败。漏检部件不能由铰链规则补回，正确类别不能修复过大把手掩码。页面场景是作者选择的有利案例，置信度显示阈值为至少 0.50，截图匹配比例不是总体 AP。

作者在 RTX 5070 Ti 上报告部件运动路径中位数 33.78 s，含超点、两个感知模型及几何解码，不含第三个联合模型。不是完整三模型耗时或实时帧率。本机相关时间与显存需求未测。

## 使用场景与对你的价值

以下为应用推断，尚未验证：机器人操作感知候选、扫描场景交互标注、数字孪生关节描述、带人工校正的资产工作台、空间 Agent 的可执行对象列表。

已有樱花小街采用程序化组件，可在创建时定义 `部件 ID / 运动类型 / 轴 / 原点 / 操作区域 / 运动范围 / 当前状态`。先形成数据合同与交互，再研究真实扫描自动标注，更贴近现有项目。游戏 Agent 可以借鉴“感知 → 对象与动作 → 执行 → 反馈”的连接方式。本阶段未修改或接入其他项目。

可按“人工校正工作台 → 引擎导出 → Agent 动作与反馈 → 多姿态轴、多帧校验”扩展。本阶段只完成说明与展示。
