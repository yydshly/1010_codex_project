对现有项目的价值 ↓

一个柜子的外观告诉我们它在哪里；操作它还需要部件、动作、轴与作用位置。这个方法把这些线索连接起来，为场景提供可以用于交互的描述。

01 / 从对象到动作

描述“可以怎样操作”

门板、运动轴和把手在同一坐标系里建立关系。完整运动范围、状态和执行反馈由交互系统补充。

02 / 关系减少歧义

小线索决定大结构

单看近似对称的门板，两侧都可能是铰链；把手位置帮助区分候选。线索的价值取决于它能排除多少种解释。

03 / 学习与约束分工

发现线索，再检查关系

学习模型识别部件与把手，几何规则组合这些结果。错误可以定位到检测、关联或规则的适用条件。

模型负责认出来，几何规则负责连接起来。

点云是很多带位置与颜色的三维采样点；掩码是“哪些点属于同一个部件”；运动轴则是旋转绕哪条线、平移沿哪个方向。只有静态表面时，门的左右两侧可能都像铰链；把手通常在便于施力的另一侧，为选择提供线索。

模型 01 · 大表面

独立部件预测

把附近的点组织成超点，通过查询预测门、抽屉等部件掩码与运动类别。它提供最终部件实例。

模型 02 · 小区域

密集把手预测

逐点判断背景、旋转把手或平移把手，再把相邻点聚成实例。它的位置用于选择铰链。

模型 03 · 部件上下文

联合部件与把手预测

用自身部件查询特征和细体素特征提出更多把手候选。它有自己的部件预测，不读取模型 01 的掩码。

把手 → 部件

让铰链落在合理的一侧

拟合部件的可靠表面，构造候选铰链线，选择距离附近把手最远的一条。旋转默认采用竖直轴，平移采用表面法线。

部件 → 把手

补充位置，修正含义

联合模型增加把手候选；独立部件类别帮助修正新增候选的旋转或平移标签，密集把手类别作为回退证据。

  1. 清理拟合支撑

    取部件最大的连通区域，用 PCA 找表面的薄方向，再用投影凸包的最小面积矩形得到包围盒。

  2. 建立候选与关联

    包围盒给出四条竖直候选线。寻找中心到部件支撑距离小于 0.5 m 的最近把手。

  3. 选择另一侧

    选离把手最远的候选线，把部件中心投影到线上作为原点。没有附近把手时回退到中心。

“免训练”指最后的几何解码规则；前面的三个感知模型都经过训练。新增把手只接受一次类别修正，不会重新反馈并改变运动轴。本页示意中的开启角度由你设定，不是模型预测。

AP 以百分数展示，差值按未四舍五入的数值计算；它不是操作成功率。运动综合指标同时检查部件掩码、轴方向与旋转铰链位置，平移原点不参与该指标。不同任务的增益不能相加。

这个对照支持什么判断？

掩码与轴都保持不变，改变把手线索的使用方式就能改善铰链位置。这支持“关系线索能减少几何歧义”的判断。结果来自参与选参的验证场景；部件漏检仍是作者分析中最大的剩余问题，迁移时要同时检查识别覆盖和规则是否适用。

05 / 能力边界

给操作提供线索，
完成操作还需要下一层。

机器人感知、扫描场景交互标注与数字孪生是可探索的应用方向。这些应用价值是研究判断，尚未在本项目验证。

01

近似平面、竖直铰链是主要假设

翻盖、斜轴、缺失把手与不完整扫描可能失败；几何规则无法补回漏检部件。

02

尚未给出完整轨迹与机器人操作

运动范围、抓取姿态、碰撞、力度和执行反馈，需要另外建模与验证。

03

当前聚焦方法与价值判断

作者结果用来评估方法作用；本地动画帮助理解输出。模型 GPU 推理尚未在本机验证。环境资料保留在来源记录中。

06 / 应用与扩展方向

把三维场景变成可操作的对象列表。

应用推断 · 尚未接入其他项目

我的判断：对你现有的程序化场景，最直接的价值是把创建资产时已知的部件与动作关系写成统一描述，让玩家和 Agent 使用同一套操作接口。识别未知扫描的需求出现后，再评估自动感知。

01 / 当前优先

对象与动作接口

给门、抽屉、按钮定义操作区域、范围、状态和动作条件，让渲染、玩家与 NPC 共用同一份描述。

02 / Agent 验证

动作带来可检查的反馈

例如让小街 NPC 打开柜门取物：选择对象、检查距离、执行开门，再返回成功或受阻。用反馈检查它能否继续任务。

03 / 按需求扩展

从扫描到复杂机构

有扫描资产需求时加入人工校正与引擎导出；研究复杂机构时再考虑非竖直轴、多帧观测与范围估计。

可先采用的交互描述 部件 ID · 运动类型 · 轴 · 原点 · 操作区域 · 运动范围 · 当前状态 · 动作条件 · 执行结果
前五项可由这类感知输出提供；范围、状态、条件与反馈由交互系统补充。直接定义程序化资产的描述后，可以先验证对象选择、动作条件与执行反馈。
